# Sche10le

Webページの日程を見つけて、Googleカレンダーへ。WXT / Manifest V3 / バニラJavaScriptで作るChrome・Safari拡張です。実行時の追加パッケージ、サーバー、OAuthは使いません。

**開発中：0.6.0 はSafari／Chrome共通UIへの移行版です。正式リリース・Safariの配布はまだです。** 最新の公開版は0.5.0です。[統合方針と公開前チェック](docs/dev/unified-0.6.0.md)を参照してください。

## 試す

Node.js 22.16以上とChrome 116以上が必要です。Safariの実行方法は[開発手順](docs/dev/safari-development.md)にまとめています。

```sh
npm ci
npm run build
```

1. Chromeの `chrome://extensions` でデベロッパーモードを有効にし、`.output/chrome-mv3` を読み込みます。
2. 日程のあるページでSche10leの拡張アイコンを押します。
3. ページ内のシート／ドロワーで日程と「時間どおり」「移動込み」「終日」を選びます。マウスはホバー、キーボードはフォーカス、タッチはタップで候補を開きます。
4. シートが取得バーに縮みます。タイトル → 場所 → 詳細をページから選択します。各項目のボタン下に現在の内容を最大2行で表示します。項目ボタンから直接移動でき、不要な項目を取得する必要はありません。
5. 取得が終わると内容の確認画面に戻ります。途中でも右上の展開ボタン（内容を確認）から進めます。取得結果の行を押せばその項目を選び直せます。
6. 「Googleカレンダーで開く」から内容を確認・修正して保存します。拡張はカレンダーへの保存完了を検知しません。

ヘッダの歯車ボタン（設定）で、移動時間・タイトル書式・カラーテーマを変更できます。「選び直す」は取得バー・確認画面の日時の横にあります。一覧の再スキャンは件数の隣です。一覧と設定にはフッタを設けず、確認画面だけカレンダーとICSの操作を下部に固定します。ドロワーは使いません。PCとモバイルの差は同じUIの幅・高さで調整します。

候補の元の文字列をページ上で強調します。特定できる場合はシートの上に見える位置へスクロールします。ページ末尾や固定要素などで隠れるときは、上部の案内帯をドラッグして表示位置を上下に移動できます。案内帯へのフォーカス後、↑↓（16px）、Shift＋↑↓（48px）、Home／Endでも移動できます。下端が初期位置です。

内容の取得は、タップ／クリックで領域全体、PCではドラッグで文字範囲を選べます。スマートフォンでは長押ししてSafari標準の選択ハンドルで範囲を調整し、取得バーの「この範囲を使う」で確定します。範囲を調整すると現在の項目ボタンにも内容をプレビューします。範囲の上・下それぞれに余白があれば、そこにも「この範囲を使う」を表示します。確定するまで取得内容は変更せず、範囲選択を解除すると元の表示へ戻ります。フォーム内の範囲は対象外です。ページ側で文字選択を禁止している箇所は、長押し選択できない場合があります。

各日付候補には登場順で A・B・C…（Zの次はAA）を付け、ソート後も同じ目印を維持します。候補カード、ページ内の強調箇所、選択後の日付表示に共通して表示します。再スキャン時には、その時点の候補で付け直します。

初回は登場順で、本文の位置を特定できない構造化データは末尾です。日時順は日付・開始時刻の昇順で、同じ開始日の終日は時刻付きより先です。最後に選んだ順序を端末に保存します。同じ日付範囲の時刻付き候補と重複する終日カードは省きますが、各候補の「終日」は残します。

タイトルの初期値はページタイトル、場所は空欄、詳細はページURLです。詳細を取得すると「取得テキスト＋空行＋元ページURL」になります。移動時間は前後30分が標準で、0〜180分へ変更できます。矢印操作は5分刻み、直接入力は1分単位の整数です。

カラーテーマは千歳緑（標準）・銀鼠・水浅葱・藍鉄・黒茶・紫紺です。最後の3色はダークテーマです。選択欄を開くと各テーマの背景・アクセント・文字の色見本が並びます。設定の「戻る」は歯車と同じ位置で切り替わります。選択中は白系の面と枠・太字、取得済みは淡い完了色と末尾のチェックを使います。3項目が完了するとカレンダーボタンに控えめな光が流れ、10秒の間隔をあけて追加2回まで繰り返します。操作を再開すると停止し、動きを減らす設定では省略します。

「×」またはEscで閉じても同じページの入力内容は残り、拡張アイコンから戻れます。ページ再読み込み・別ページへの移動・SPAのURL変更で破棄します。別タブの予定は独立しています。通常のページ表示・タブ切替だけではスキャンしません。読み取れないページでは拡張の案内ページを表示します。

## 予定ファイルのダウンロード

予定を選ぶと「Googleカレンダーで開く」の隣にダウンロードアイコンが表示されます。ホバー時の案内は「予定をダウンロード（.ics）」です。取得途中でも使え、選択状態はそのまま残ります。

選んだ登録パターン、移動時間、タイトル書式、場所、詳細と元ページURLを反映した `.ics` を端末内で生成します。Googleカレンダーに渡す予定と同じ内容です。終日・複数日・日またぎにも対応し、時刻付き予定はUTC、終日は日付だけで記録します。ファイルを対応するカレンダーで開くかインポートして保存してください。表示する時間帯や取り込み方法は取り込み先の設定に従います。

追加パッケージや追加権限、ファイル生成のための外部通信はありません。形式は [iCalendar（RFC 5545）](https://www.rfc-editor.org/rfc/rfc5545.html) に従います。各カレンダーアプリへの取り込み動作は別途確認が必要です。

## 設定

設定を開くと日程一覧から専用画面に切り替わります。移動時間・タイトル書式・カラーテーマは変更時に自動保存し、保存ボタンは設けません。入力エラーは赤字で示し、直前の有効な設定を維持します。保存に失敗した場合は変更をその場では維持し、「再試行」を表示します。「戻る」で一覧または確認画面へ戻れます。Escは拡張UI全体を閉じます。

## タイトルの書式

設定の「タイトルの書式」で、固定の文字と変数を組み合わせます。初期値は `{title}`。例えば `{from:HHmm} {title} あいうえお` は `1730 勉強会 あいうえお` になります。有効な書式は入力と同時にタイトルへ適用し、自動保存します。

| 変数                                                | 内容・例                                         |
| --------------------------------------------------- | ------------------------------------------------ |
| `{title}`                                           | ページタイトル、またはページから取得したタイトル |
| `{from:HHmm}` / `{to:HHmm}`                         | 開始・終了時刻。例: `1730`                       |
| `{from:HH:mm}` / `{to:HH:mm}`                       | 開始・終了時刻。例: `17:30`                      |
| `{date:YYYY-MM-DD}`                                 | 開始日。例: `2026-11-08`                         |
| `{date:YYYY/MM/DD}` / `{date:MM/DD}` / `{date:M/D}` | `2026/11/08` / `11/08` / `11/8`                  |

`{from}`・`{to}` は `HH:mm`、`{date}` は `YYYY-MM-DD` を省略時の形式にします。`hhmm` も `HHmm` と同じ24時間表記として受け付けます。`{from}`・`{to}` は移動時間を含まない元の開催時刻です。例えば17:30〜19:00の予定に前後30分の移動を加えても、タイトルには17:30と19:00を使い、カレンダーでは17:00〜19:30を確保します。`{date}` は従来どおり登録する予定の開始日で、移動で前日にまたがる場合は前日になります。終日では時刻の変数が空になります。変数の周囲に書いた記号はそのまま残ります。

取得元のタイトルと書式は別々に保持するため、タイトルを何度選び直しても装飾は重複しません。選択中のプレビューとGoogleカレンダーには同じ書式を使います。未対応の変数や書式は赤いエラー枠で表示し、最後に適用できた書式を維持します。保存に失敗した場合は赤字で知らせ、「再試行」から保存をやり直せます。

## 開発と検証

配色・書体・UIの状態と動き・アイコン・ストア素材は、[デザインシステム資料（HTML）](docs/design/design-system.html)にまとめています。HTML内にMarkdown全文とダウンロードボタンがあります。[更新手順](docs/design/README.md)も参照してください。

```sh
npm run dev        # 開発用ビルドと変更監視
npm run check      # lint / JSDoc型検査 / 単体テスト / 本番ビルド
npx playwright install chromium webkit  # 初回のみ
npm run test:ui    # 共通UIをChromium/WebKitで検証
npm run test:e2e   # 本番ビルド後に実行
npm run zip       # 配布用ZIPを生成
npm run icons     # ブランドのCSS原稿から各サイズのPNGを再生成（macOS）
```

開発中は `.output/chrome-mv3-dev` をChromeに読み込みます。ブラウザの自動起動は無効にしています。ランナー用の追加依存を増やさず、既存のChromeで確認できます。

配布用アイコンは `public/icons/` にあります。ストアには `128.png`（128×128px）を使用します。再生成はGeorgiaを使用できるmacOSとPlaywrightのChromiumで行い、`lib/brand.css` が参照する `lib/brand-mark.svg` のマーク原稿をそのまま描画します。生成済みPNGを同梱するため、利用者の端末にGeorgiaがなくても配布用アイコンの見た目は変わりません。

main向けPRとmainへのpushでは、`Regression` ワークフローがlint・型検査・単体テスト・両ブラウザ向けビルド・Chrome実拡張・Chromium/WebKit共通UIを検証します。外部イベントサイトの検証とは分離しています。詳しくは [CIの運用](scripts/ci/README.md) を参照してください。

ブラウザテストは一時プロファイルとローカルのfixtureを使用します。ツールバーのクリックによる `activeTab` の付与を自動化できないため、**テスト用コピーだけ**に `127.0.0.1` のホスト権限を追加します。本番manifestにホスト権限や自動実行Content Scriptがないことも検査します。実際のContent Scriptをページに注入し、ドロワー内での取得・ページ遷移・設定保存を確認します。

E2Eはブラウザコンテキストを共有しています。`page.clock` による時計の停止・時刻変更は後続ページにも影響するため、使ったテストの `finally` で `setSystemTime(new Date())` と `resume()` を実行します。ページを閉じるだけでは時計は復元されません。

カレンダーへの受け渡しは `chrome.tabs.create` に渡されたURLを検査し、テストでは実際の遷移先を空白タブに置き換えます。Googleカレンダーへのログイン・予定保存は行いません。実際のツールバーからの起動と権限を許可・拒否した場合の動作は手動確認が必要です。

### Safari版

Safari版はiPhone向けの下部シートとMac向けのドロワーを開発中です。`npm run preview:safari` でUIプレビュー、`npm run prepare:safari` でSafari用MV3を生成してXcode向けバージョンを同期できます。Git管理するプロジェクトは `native/safari/Sche10le.xcodeproj` です。ローカルAIは含みません。まだSafari拡張としての実機検証・配布準備は完了していません。共有方針、専用テスト、Xcode導入と実機確認は [Safari版の開発手順](docs/dev/safari-development.md) を参照してください。

## 変更履歴と配布用ビルド

バージョンごとの変更は [CHANGELOG.md](CHANGELOG.md) を参照してください。現在の配布タグは `v0.5.0` です。タグの内容からZIPを作る場合は、作業中の変更を退避してから実行します。

```sh
git fetch --tags
git switch --detach v0.5.0
npm ci
npm run zip
```

Chrome Web Storeへアップロードするファイルは **`.output/sche10le-0.5.0-chrome.zip`** です。ZIP内の `manifest.json` のバージョンも `0.5.0` になります。ビルド後に通常の開発へ戻る場合は `git switch main` を実行します。

変更してから配布する場合は、`npm run check` と `npm run test:e2e` も実行してください（ブラウザテストの初回準備は `npx playwright install chromium`）。ライブサイトの結果は配布するコミットに対応するものを確認します。バージョン更新時は `package.json`・`package-lock.json`・CHANGELOG・関連資料をそろえてからタグを作成します。

## 公開前のライブサイト検証

connpass・Doorkeeper・Peatix・TECH PLAY・こくちーずプロ・Meetup・Lumaの公開イベントページを、その都度Chromiumで開いて本番ビルドの拡張で検証します。HTMLのコピーは保存しません。通常の `npm test` / `npm run test:e2e` / `npm run check` では実サイトへアクセスしません。

PRが **mainにマージされたとき** に、CI標準対象（`sites=ci`）を自動検証します。こくちーずプロはGitHub ActionsからHTTP応答を確認できないため標準対象外とし、理由付きで未検証として報告します。PRの作成・更新中、マージせずに閉じた場合、mainへの直接pushでは検証しません。必要なときはGitHub Actionsの **Live event sites → Run workflow → main** から手動実行でき、対象サイトも絞れます。ストア更新前にはアップロード対象コミットのCI結果と、こくちーずプロのローカル検証結果を確認してください。週次実行は運用が安定してから検討します。

ローカルでは `npm run build` の後に `npm run test:live` で全登録サイトを検証します。対象を絞る場合は `LIVE_SITES=connpass,meetup npm run test:live` を使います。WFの手動実行も `sites` にIDを指定でき、例えば `kokuchpro` でこくちーずプロだけを再調査できます。`all` を明示すればCIでも除外せず全登録サイトを検証します。開始・終了日時の両方を検証し、結果は `test-results/live/report.json` と `summary.md` に出力します。CIでは実行サマリーと14日間保存するArtifactから確認できます。実行対象のアクセス制限やページ消失は失敗とし、自動除外して成功扱いにはしません。

サイトの追加は原則として [tests/live/sites.js](tests/live/sites.js) にURL・識別文・期待日時・最終確認日を1項目追加するだけです。`npm run check:live-samples` で外部アクセスなしに見直し時期を確認できます。負荷の制限、結果の読み方、追加・更新方法は [ライブテストの運用手順](tests/live/README.md) を参照してください。

## 日付・時刻の対応範囲

以下は通常スキャンの対応です。本文は最大100,000文字、候補は最大100件。例で年が省略されている場合は、2026年にスキャンしたものとして示します。

**年も時刻もない単独の月日は、ノイズを減らすため本文スキャンから除外します。** 例えば分数の `2/3`、`11月8日`、`Nov 8` は候補にしません。`11/8 14:00` のような時刻付き、`2026/11/8` のような年付き、`11/8〜11/10` のような両端に月日がある期間は引き続き対象です。JSON-LDに明示された終日イベントも対象です。近くに無関係な時刻がある場合の誤検出まで防ぐものではありません。

### 対応している日付

| 種類                     | 入力例                                             | 解釈・条件                                         |
| ------------------------ | -------------------------------------------------- | -------------------------------------------------- |
| 西暦・日本語             | `2026年11月8日`                                    | 2026-11-08                                         |
| 西暦・数値区切り         | `2026/11/8`、`2026-11-08`、`2026.11.8`             | 年→月→日の順。区切りの前後の空白も可               |
| 年省略                   | `11月8日 14時`、`11/8 14:00`、`11-8 14:00`                          | 時刻が必要。スキャンした年の11月8日。過去の日でも翌年にはしない        |
| 全角数字・記号           | `２０２６年１１月８日`、`１４：００`               | 半角へ正規化して扱う                               |
| 令和・数字年             | `令和8年11月8日`、`令和８年１１月８日`             | 2018＋令和の年数で換算 → 2026-11-08                |
| 令和元年                 | `令和元年5月1日`、`令和1年5月1日`                  | 2019-05-01。令和0年や2019-05-01より前の日付は除外  |
| 英語・月→日→年           | `November 8, 2026`、`Nov 8 2026`                   | 2026-11-08                                         |
| 英語・日→月→年           | `8 November 2026`、`8 Nov. 2026`                   | 2026-11-08                                         |
| 英語・序数・大文字小文字 | `Nov. 8th, 2026`、`8th NOV 2026`                   | 序数の末尾 `st` / `nd` / `rd` / `th` を受け付ける  |
| 英語・年省略             | `Nov 8 2 PM`、`8 November 14:00`                              | 時刻が必要。スキャンした年の11月8日                        |
| 日付範囲                 | `2026年11月8日〜11月10日`、`Nov 8, 2026 to Nov 10` | 11月8日から10日までを含む終日予定                  |
| 年をまたぐ範囲           | `令和8年12月31日〜1月2日`、`Dec 31, 2026 to Jan 2` | 2026-12-31〜2027-01-02。終点の省略年は始点から補う |

英語の月名はJanuary〜Decemberの12か月に対応。省略形は `Jan` / `Feb` / `Mar` / `Apr` / `May` / `Jun` / `Jul` / `Aug` / `Sep`（`Sept`も可）/ `Oct` / `Nov` / `Dec` で、末尾のピリオドも可です。曜日の正しさまでは検証しません。年は1900〜2199年の範囲で、うるう日を含め実在する日付かを検証します。

### 対応している時刻

| 種類             | 入力例                                | 解釈・条件                                             |
| ---------------- | ------------------------------------- | ------------------------------------------------------ |
| 24時間表記       | `14:00〜16:00`、`14:00–16:00`         | 14時〜16時                                             |
| 日本語の時・分   | `14時〜16時`、`14時30分〜16時`        | 24時間表記として解釈                                   |
| 午前・午後       | `午後2時〜4時`、`午前11時〜午後1時`    | 14:00〜16:00、11:00〜13:00。コロン表記・全角数字も可 |
| AM/PM            | `2 PM–4 PM`、`2:30 p.m. to 4:30 p.m.` | 14時〜16時、14:30〜16:30。大文字小文字・ピリオドに対応 |
| 正午・深夜       | `12 AM–12 PM`                         | 00:00〜12:00                                           |
| 日をまたぐ時間帯 | `23:00〜01:00`、`11 PM–1 AM`          | 終了時刻を翌日として扱う                               |
| 開始だけ         | `15時`、`2 PM`                        | 終了を仮に1時間後とし、画面にもその旨を表示            |

時刻は日付の直後から最大180文字・3行の範囲で読みます。同じ日付に複数の時間帯があれば、それぞれを候補にします。本文中の時刻は端末のタイムゾーンで解釈します。AM/PMの時間帯は**両端にAM/PMを明示**してください。午前・午後は0〜12時を受け付け、午前0時・12時＝00時、午後0時・12時＝12時です。終点の午前・午後を省略できるのは、同じ午前／午後の中で終了が開始より後になる場合だけです。日またぎは `午後11時〜午前1時` のように両端を明示します。

### 未対応の表記・注意点

| 種類                 | 未対応の例                                               | 現在の扱い                                                                     |
| -------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 令和以外の元号       | `平成30年11月8日`、`昭和64年1月7日`                      | 年を換算しない。上記のような年月日は全体を除外し、月日だけを拾わない           |
| 令和の略記           | `R8.11.8`、`R8/11/8`                                     | 除外。`令和8年11月8日` を使用                                                  |
| 漢数字               | `令和八年11月8日`、`二〇二六年十一月八日`、`十四時`      | 漢数字の数値変換はしない。`元年`のみ例外                                       |
| 数値の月日年・日月年 | `11/08/2026`、`08/11/2026`                               | 月日の順序を推測せず除外。`2026-11-08` または英語月名を使用                    |
| 2桁の西暦年          | `11/08/26`、`Nov 8, 26`                                  | 除外。年は4桁で指定                                                            |
| AM/PMの一部省略      | `2–4 PM`、`2:00–4:00 PM`、`2 PM–4`                       | 曖昧な時間帯を推測せず除外。`2 PM–4 PM` を使用                                 |
| 午前・午後の曖昧な省略 | `午後11時〜1時`、`2時〜午後4時`                        | 午前・午後や翌日を推測せず除外。両端を明示する |
| 短縮した日付範囲     | `Nov 8–10, 2026`、`11月8〜10日`                          | 月・年の補完は未対応。一部だけ拾う場合がある。両端に月日を書く                 |
| 24時表記・秒         | `24:00`、`14:00:30`                                      | 24時は無効。秒は扱わず分までの部分を拾う場合がある                             |
| 本文のタイムゾーン   | `2 PM EST`、`14:00 UTC+09:00`、`14:00–16:00 PST`         | 対応するゾーン表記を近傍で検出した場合、その日付の本文候補を除外。換算はしない |
| 相対日付・繰り返し   | `明日`、`来週火曜`、`毎月第2水曜`                        | 未対応。相対日付を推測しない                   |
| その他の言語・入力元 | 英語以外の月名、画像内の文字、iframe内、閉じたShadow DOM | 対象外                                                                         |

タイムゾーンの除外判定は、日付の前方同一行100文字までと、後方180文字・3行まで（別の日付まで）に限定します。UTC/GMT、JST/KST、EST/EDT・CST/CDT・MST/MDT・PST/PDT・AST/ADT・HST/HDT、CET/CEST・EET/EEST・BST/IST、HKT/SGT、AEST/AEDT・ACST/ACDT・AWST・NZST/NZDT、`Asia/Tokyo` などの地域名、日本時間・日本標準時・協定世界時を検出します。`+09:00`・`-0800`、ISO日時の `Z`・負のオフセット、時間帯末尾の `-08:00` も除外します。単独の `14:00-08:00` は翌朝までの時間帯との区別がつかないため、従来どおり時間帯として扱います。離れた見出しのゾーン指定や、一覧にない略称・自然文は網羅しません。同じ近傍にある別の時刻も保守的に除外する場合があります。JSON-LDの明示オフセット付き日時は引き続き換算して利用します。

未対応表記をすべて安全に除外できるわけではありません。本文の構成によって部分抽出・誤検出・見落としがあり得るため、候補の出典表示と登録前の日時を確認してください。対応例・境界値・除外例は `tests/date-formats.test.js` と `tests/events.test.js` で検証しています。

### 構造化データと処理の重さ

ページにJSON-LDのEvent系オブジェクトがあれば、本文の言語に関係なくISO日時を抽出します。例: `2026-11-08`、`2026-11-08T14:00:00+09:00`。配列・`@graph`にも対応し、UTCオフセット付き日時は保持して端末のタイムゾーンで表示します。同じ日時は本文抽出と統合し、構造化データを優先します。

令和・英語は固定の書式と12か月の対応表で処理し、汎用の自然言語解析や日付ライブラリは追加していません。出典の文字位置を保つため、令和や英語月名を本文全体で別の文字列へ置換する処理も行いません。

## 0.6.0 での機能変更

ChromeのローカルAI補完は一旦提供を停止します。通常の日程スキャンは維持します。共通版が安定した後、Chromeのみへの再導入を検討します。旧AI設定は読み込まず、モデルの起動・ダウンロードも行いません。

## 権限とデータ

| 権限        | 用途                                           |
| ----------- | ---------------------------------------------- |
| `activeTab` | 拡張アイコンを押したページへの一時的なアクセス |
| `scripting` | 必要なときだけDOM取得・選択UIを注入            |
| `storage`   | 移動時間・タイトル書式・並び順・テーマの保存           |

ページ内容・候補・取得内容は永続保存しません。設定のみ端末内に保存します。解析は端末内で完結し、カレンダーを開く操作で選択した予定情報と元ページURLをGoogleへ渡します。解析用サーバー・アクセス解析・外部フォントはありません。

設計の詳細は [製品・技術設計書](docs/dev/product_technical_design.md) を参照してください。
