# Sche10le

Webページの日程を見つけて、Googleカレンダーへ。WXT / Manifest V3 / バニラJavaScriptで作るChrome拡張です。実行時の追加パッケージ、サーバー、OAuthは使いません。

## 試す

Node.js 22.16以上とChrome 116以上が必要です。

```sh
npm ci
npm run build
```

1. Chromeで `chrome://extensions` を開き、デベロッパーモードを有効にします。
2. 「パッケージ化されていない拡張機能を読み込む」から `.output/chrome-mv3` を選びます。
3. 日程のあるページでSche10leの拡張アイコンを押します。
4. 候補にホバー、またはキーボードでフォーカスし、「時間どおり」「移動込み」「終日で確保」から選びます。
5. ページ上のタイトル → 場所 → 詳細をクリックして取得します。各項目はスキップでき、**どの段階でもサイドパネル下部の「Googleカレンダーで開く」で先へ進めます**。ページ下部の操作バーは項目の選択・戻る・スキップ・閉じる操作に使います。
6. Googleカレンダーで内容を確認して保存します。拡張から保存完了は検知しません。

見出し右の「登場順／日時順」で候補を並べ替えられます。初回は本文での登場順。本文の位置を特定できない構造化データは末尾に置きます。日時順は日付・開始時刻の昇順で、同じ開始日の終日予定は時刻付きより先、同じ日時なら登場順です。選んだ順序は端末内に自動保存し、再スキャン・選び直し後も、パネルを閉じて開き直した後も維持します。保存に失敗した場合だけ赤い案内と「再試行」を表示します。AIの追加候補にも同じ順序を適用します。

一覧では、時刻付き候補と開始日・終了日が同じ終日候補を省きます。時間帯の異なる候補はそのまま残し、どの候補からもホバー後に「終日で確保」を選べます。単日と複数日にわたる期間は別々に残します。AI補完中に予定を選んだ場合は、その選択と取得済みの項目を維持し、一覧に戻ったときに候補を整理します。

タイトルの初期値はページタイトル、場所は空欄、詳細はページURLです。詳細を取得すると「取得テキスト＋空行＋元ページURL」になります。移動込みは初期値が前後30分で、設定から0〜180分に変更できます。移動時間の矢印操作は5分刻みです（直接入力は1分単位の整数も受け付けます）。

ページ上の取得を一時停止するには操作バーの「閉じる」または `Esc`。取得済みの内容を残してページの通常操作に戻れます（別ページへ移動すると選択は解除されます）。開始時には操作バーを短く強調し、「ページ上の文字をクリック」と、取り込む項目名を案内します。操作バーは手順が進んでも同じ大きさとボタン位置を保ちます。タイトル選択時の「戻る」、取得完了後の「スキップ」は無効状態で残ります。詳細を選択中の「スキップ」は使えます。3項目を取得し終わってもページ下部の操作バーは残ります。「戻る」または「タイトル／場所／詳細」の項目ボタンから直接選び直せます。サイドパネルは取得内容の確認用です。取得結果の行をクリックするか、キーボードでフォーカスしてEnter／Spaceを押すと、その項目を選び直せます。選択中の行には「選択中」を表示し、ホバー・キーボードフォーカス時は編集アイコンを表示します。一時停止した場合は「ページから取得を再開」も使えます。完了後は本文の通常クリックを妨げません。取得した欄は短く光り、チェックで完了を知らせます（動きを減らす設定ではチェックのみ）。リンク上の文字も、取得中はページ遷移せず選択できます。入力欄や編集可能な領域は取得対象外です。

別タブ・別ページへ移動すると取得を解除します。新しいページで拡張アイコンを押してアクセスを許可してください。サイドパネル内の再スキャンは、そのページへのアクセス権限が残っている場合に使えます。

候補にホバー、またはキーボードでフォーカスすると、約180ms後に元の日時へスクロールし、文字列の周囲が波打つように光ります。対象部分の明るさを保ちながらページの残りを暗くし、小さい文字も見つけやすくします。改行された文字列にも対応し、ページの操作は妨げません。候補から離れるかパターンを選ぶと解除します。動きを減らす設定ではスクロール・強調とも静的に切り替えます。構造化データだけの候補など、本文中に元の文字列を特定できない場合やスキャン後に文字列が変わった場合はスクロールしません。

上部の「再スキャン」はアイコンと文字のボタンです。対象ページの表示はドメイン名とスキャン状態に絞り、ページタイトルはドメイン名にホバーすると確認できます。

スキャンするのは、サイドパネルの初回読み込み時・拡張アイコンを押したとき・再スキャンを押したときです。通常のページ表示やタブ切替だけでは自動スキャンしません。

## 設定

設定を開くと日程一覧から専用画面に切り替わります。移動時間・タイトル書式・AI補完はすべて変更時に自動保存し、保存ボタンは設けません。入力エラーは赤字で示し、直前の有効な設定を維持します。保存に失敗した場合は変更をその場では維持し、該当項目にだけ共通の「再試行」を表示します。「閉じる」またはEscで選択中の予定に戻れます。

## タイトルの書式

設定の「タイトルの書式」で、固定の文字と変数を組み合わせます。初期値は `{title}`。例えば `{from:HHmm} {title} あいうえお` は `1730 勉強会 あいうえお` になります。有効な書式は入力と同時にタイトルへ適用し、自動保存します。

| 変数                                                | 内容・例                                         |
| --------------------------------------------------- | ------------------------------------------------ |
| `{title}`                                           | ページタイトル、またはページから取得したタイトル |
| `{from:HHmm}` / `{to:HHmm}`                         | 開始・終了時刻。例: `1730`                       |
| `{from:HH:mm}` / `{to:HH:mm}`                       | 開始・終了時刻。例: `17:30`                      |
| `{date:YYYY-MM-DD}`                                 | 開始日。例: `2026-11-08`                         |
| `{date:YYYY/MM/DD}` / `{date:MM/DD}` / `{date:M/D}` | `2026/11/08` / `11/08` / `11/8`                  |

`{from}`・`{to}` は `HH:mm`、`{date}` は `YYYY-MM-DD` を省略時の形式にします。`hhmm` も `HHmm` と同じ24時間表記として受け付けます。`{from}`・`{to}` は移動時間を含まない元の開催時刻です。例えば17:30〜19:00の予定に前後30分の移動を加えても、タイトルには17:30と19:00を使い、カレンダーでは17:00〜19:30を確保します。`{date}` は従来どおり登録する予定の開始日で、移動で前日にまたがる場合は前日になります。終日では時刻の変数が空になります。変数の周囲に書いた記号はそのまま残ります。

取得元のタイトルと書式は別々に保持するため、タイトルを何度選び直しても装飾は重複しません。選択中のプレビューとGoogleカレンダーには同じ書式を使います。未対応の変数や書式は赤いエラー枠で表示し、最後に適用できた書式を維持します。保存に失敗した場合は赤字で知らせ、「再試行」から保存をやり直せます。

## 開発と検証

```sh
npm run dev        # 開発用ビルドと変更監視
npm run check      # lint / JSDoc型検査 / 単体テスト / 本番ビルド
npx playwright install chromium  # 初回のみ
npm run test:e2e   # 本番ビルド後に実行
npm run zip       # 配布用ZIPを生成
npm run icons     # ヘッダーと同じデザインで各サイズのPNGを再生成（macOS）
```

開発中は `.output/chrome-mv3-dev` をChromeに読み込みます。ブラウザの自動起動は無効にしています。ランナー用の追加依存を増やさず、既存のChromeで確認できます。

配布用アイコンは `public/icons/` にあります。ストアには `128.png`（128×128px）を使用します。再生成はGeorgiaを使用できるmacOSとPlaywrightのChromiumで行い、サイドパネルの `.brand-mark` のCSS・色をそのまま描画します。生成済みPNGを同梱するため、利用者の端末にGeorgiaがなくても配布用アイコンの見た目は変わりません。

ブラウザテストは一時プロファイルとローカルのfixtureを使用します。ツールバーのクリックによる `activeTab` の付与を自動化できないため、**テスト用コピーだけ**に `127.0.0.1` のホスト権限を追加します。本番manifestにホスト権限や自動実行Content Scriptがないことも検査します。サイドパネルのHTMLを拡張ページとして開き、実際のContent Scriptとの通信・DOM取得・ページ遷移・設定保存を確認します。

カレンダーへの受け渡しは `chrome.tabs.create` に渡されたURLを検査し、テストでは実際の遷移先を空白タブに置き換えます。Googleカレンダーへのログイン・予定保存は行いません。実際のツールバーからの起動とChrome標準サイドパネルの開閉は手動確認が必要です。

## 日付・時刻の対応範囲

以下は**ローカルAIを使わない通常スキャン**の対応です。本文は最大100,000文字、候補は最大100件。例で年が省略されている場合は、2026年にスキャンしたものとして示します。

**年も時刻もない単独の月日は、ノイズを減らすため本文スキャンから除外します。** 例えば分数の `2/3`、`11月8日`、`Nov 8` は候補にしません。`11/8 14:00` のような時刻付き、`2026/11/8` のような年付き、`11/8〜11/10` のような両端に月日がある期間は引き続き対象です。JSON-LDに明示された終日イベントも対象です。近くに無関係な時刻がある場合の誤検出まで防ぐものではありません。

### 対応している日付

| 種類                     | 入力例                                             | 解釈・条件                                         |
| ------------------------ | -------------------------------------------------- | -------------------------------------------------- |
| 西暦・日本語             | `2026年11月8日`                                    | 2026-11-08                                         |
| 西暦・数値区切り         | `2026/11/8`、`2026-11-08`、`2026.11.8`             | 年→月→日の順。区切りの前後の空白も可               |
| 年省略                   | `11月8日 14時`、`11/8 14:00`、`11-8 14:00`                          | 時刻が必要。スキャンした年の11月8日。過去の日でも翌年にはしない        |
| 全角数字・記号           | `２０２６年１１月８日`、`１４：００`               | 半角へ正規化して扱う                               |
| 令和・数字年             | `令和8年11月8日`、`令和８年１１月８日`             | 2018＋令和の年数で換算 → 2026-11-08                |
| 令和元年                 | `令和元年5月1日`、`令和1年5月1日`                  | 2019-05-01。令和0年や2019-05-01より前の日付は除外  |
| 英語・月→日→年           | `November 8, 2026`、`Nov 8 2026`                   | 2026-11-08                                         |
| 英語・日→月→年           | `8 November 2026`、`8 Nov. 2026`                   | 2026-11-08                                         |
| 英語・序数・大文字小文字 | `Nov. 8th, 2026`、`8th NOV 2026`                   | 序数の末尾 `st` / `nd` / `rd` / `th` を受け付ける  |
| 英語・年省略             | `Nov 8 2 PM`、`8 November 14:00`                              | 時刻が必要。スキャンした年の11月8日                        |
| 日付範囲                 | `2026年11月8日〜11月10日`、`Nov 8, 2026 to Nov 10` | 11月8日から10日までを含む終日予定                  |
| 年をまたぐ範囲           | `令和8年12月31日〜1月2日`、`Dec 31, 2026 to Jan 2` | 2026-12-31〜2027-01-02。終点の省略年は始点から補う |

英語の月名はJanuary〜Decemberの12か月に対応。省略形は `Jan` / `Feb` / `Mar` / `Apr` / `May` / `Jun` / `Jul` / `Aug` / `Sep`（`Sept`も可）/ `Oct` / `Nov` / `Dec` で、末尾のピリオドも可です。曜日の正しさまでは検証しません。年は1900〜2199年の範囲で、うるう日を含め実在する日付かを検証します。

### 対応している時刻

| 種類             | 入力例                                | 解釈・条件                                             |
| ---------------- | ------------------------------------- | ------------------------------------------------------ |
| 24時間表記       | `14:00〜16:00`、`14:00–16:00`         | 14時〜16時                                             |
| 日本語の時・分   | `14時〜16時`、`14時30分〜16時`        | 24時間表記として解釈                                   |
| 午前・午後       | `午後2時〜4時`、`午前11時〜午後1時`    | 14:00〜16:00、11:00〜13:00。コロン表記・全角数字も可 |
| AM/PM            | `2 PM–4 PM`、`2:30 p.m. to 4:30 p.m.` | 14時〜16時、14:30〜16:30。大文字小文字・ピリオドに対応 |
| 正午・深夜       | `12 AM–12 PM`                         | 00:00〜12:00                                           |
| 日をまたぐ時間帯 | `23:00〜01:00`、`11 PM–1 AM`          | 終了時刻を翌日として扱う                               |
| 開始だけ         | `15時`、`2 PM`                        | 終了を仮に1時間後とし、画面にもその旨を表示            |

時刻は日付の直後から最大180文字・3行の範囲で読みます。同じ日付に複数の時間帯があれば、それぞれを候補にします。本文中の時刻は端末のタイムゾーンで解釈します。AM/PMの時間帯は**両端にAM/PMを明示**してください。午前・午後は0〜12時を受け付け、午前0時・12時＝00時、午後0時・12時＝12時です。終点の午前・午後を省略できるのは、同じ午前／午後の中で終了が開始より後になる場合だけです。日またぎは `午後11時〜午前1時` のように両端を明示します。

### 未対応の表記・注意点

| 種類                 | 未対応の例                                               | 現在の扱い                                                                     |
| -------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 令和以外の元号       | `平成30年11月8日`、`昭和64年1月7日`                      | 年を換算しない。上記のような年月日は全体を除外し、月日だけを拾わない           |
| 令和の略記           | `R8.11.8`、`R8/11/8`                                     | 除外。`令和8年11月8日` を使用                                                  |
| 漢数字               | `令和八年11月8日`、`二〇二六年十一月八日`、`十四時`      | 漢数字の数値変換はしない。`元年`のみ例外                                       |
| 数値の月日年・日月年 | `11/08/2026`、`08/11/2026`                               | 月日の順序を推測せず除外。`2026-11-08` または英語月名を使用                    |
| 2桁の西暦年          | `11/08/26`、`Nov 8, 26`                                  | 除外。年は4桁で指定                                                            |
| AM/PMの一部省略      | `2–4 PM`、`2:00–4:00 PM`、`2 PM–4`                       | 曖昧な時間帯を推測せず除外。`2 PM–4 PM` を使用                                 |
| 午前・午後の曖昧な省略 | `午後11時〜1時`、`2時〜午後4時`                        | 午前・午後や翌日を推測せず除外。両端を明示する |
| 短縮した日付範囲     | `Nov 8–10, 2026`、`11月8〜10日`                          | 月・年の補完は未対応。一部だけ拾う場合がある。両端に月日を書く                 |
| 24時表記・秒         | `24:00`、`14:00:30`                                      | 24時は無効。秒は扱わず分までの部分を拾う場合がある                             |
| 本文のタイムゾーン   | `2 PM EST`、`14:00 UTC+09:00`、`14:00–16:00 PST`         | 対応するゾーン表記を近傍で検出した場合、その日付の本文候補を除外。換算はしない |
| 相対日付・繰り返し   | `明日`、`来週火曜`、`毎月第2水曜`                        | 通常スキャンでは未対応。ローカルAIによる相対日付の補完は任意                   |
| その他の言語・入力元 | 英語以外の月名、画像内の文字、iframe内、閉じたShadow DOM | 対象外                                                                         |

タイムゾーンの除外判定は、日付の前方同一行100文字までと、後方180文字・3行まで（別の日付まで）に限定します。UTC/GMT、JST/KST、EST/EDT・CST/CDT・MST/MDT・PST/PDT・AST/ADT・HST/HDT、CET/CEST・EET/EEST・BST/IST、HKT/SGT、AEST/AEDT・ACST/ACDT・AWST・NZST/NZDT、`Asia/Tokyo` などの地域名、日本時間・日本標準時・協定世界時を検出します。`+09:00`・`-0800`、ISO日時の `Z`・負のオフセット、時間帯末尾の `-08:00` も除外します。単独の `14:00-08:00` は翌朝までの時間帯との区別がつかないため、従来どおり時間帯として扱います。離れた見出しのゾーン指定や、一覧にない略称・自然文は網羅しません。同じ近傍にある別の時刻も保守的に除外する場合があります。JSON-LDの明示オフセット付き日時は引き続き換算して利用します。

未対応表記をすべて安全に除外できるわけではありません。本文の構成によって部分抽出・誤検出・見落としがあり得るため、候補の出典表示と登録前の日時を確認してください。対応例・境界値・除外例は `tests/date-formats.test.js` と `tests/events.test.js` で検証しています。

### 構造化データと処理の重さ

ページにJSON-LDのEvent系オブジェクトがあれば、本文の言語に関係なくISO日時を抽出します。例: `2026-11-08`、`2026-11-08T14:00:00+09:00`。配列・`@graph`にも対応し、UTCオフセット付き日時は保持して端末のタイムゾーンで表示します。同じ日時は本文抽出と統合し、構造化データを優先します。

令和・英語は固定の書式と12か月の対応表で処理し、汎用の自然言語解析や日付ライブラリは追加していません。出典の文字位置を保つため、令和や英語月名を本文全体で別の文字列へ置換する処理も行いません。任意のローカルAIで未対応表記を補完できる場合はありますが、形式ごとの対応・正確性は保証していません。

## ローカルAI（任意）

設定で有効にすると `LanguageModel` の利用可否を確認し、機械的な結果の後に相対日付などの候補を追加します。デフォルトは無効です。初回ダウンロードが必要なら「AIを準備する」を表示します。AIが使えない・失敗した場合も通常の抽出は動作します。

AIの処理中も候補を操作できます。取得中のタイトル・場所・詳細をAIが変更することはありません。AI出力は日付形式と原文引用を検証しますが、解釈の正確さを保証するものではないため、候補にAI補完と表示します。

AI APIの成功・失敗・セッション破棄はモックで検証しています。Gemini Nanoの実機推論は、対応Chrome・モデル・端末で別途確認してください。

## 権限とデータ

| 権限        | 用途                                           |
| ----------- | ---------------------------------------------- |
| `activeTab` | 拡張アイコンを押したページへの一時的なアクセス |
| `scripting` | 必要なときだけDOM取得・選択UIを注入            |
| `sidePanel` | 候補一覧と取得の進行表示                       |
| `storage`   | 移動時間・タイトル書式・AI設定・並び順の保存           |

ページ内容・候補・取得内容は永続保存しません。設定のみ端末内に保存します。解析は端末内で完結し、カレンダーを開く操作で選択した予定情報と元ページURLをGoogleへ渡します。解析用サーバー・アクセス解析・外部フォントはありません。

パネルを開くたびに1つをランダムに表示します。再スキャンや選び直しでは変えず、時間経過による切り替えもしません。同じことばが続く場合もあります。表示は日本語の独自訳、ホバーすると英語原文と出典を表示します。文言は拡張に同梱し、外部へ取得しに行きません。

| 日本語表示（独自訳） | 英語原文・定型表現 | 出典・確認先 |
| --- | --- | --- |
| 失った時間は二度と戻らない。 | Lost Time is never found again. | [フランクリン編『Poor Richard Improved』（1748年）](https://founders.archives.gov/documents/Franklin/01-03-02-0103) |
| 1分遅れるより、3時間早いほうがいい。 | Better three hours too soon than a minute too late. | [シェイクスピア『ウィンザーの陽気な女房たち』第2幕第2場、フォードの台詞](https://www.folger.edu/explore/shakespeares-works/the-merry-wives-of-windsor/read/2/2/) |
| 時を殺せば、永遠も傷つく。 | As if you could kill time without injuring eternity. | [ヘンリー・デイヴィッド・ソロー『Walden』「Economy」](https://www.gutenberg.org/files/205/205-h/205-h.htm) |
| 動け、いま生きているこの時に。 | Act,--act in the living Present! | [ヘンリー・ワズワース・ロングフェロー「A Psalm of Life」](https://poets.org/poem/psalm-life) |
| 時も潮も、人を待たない。 | Time and tide wait for no man. | [英語のことわざ（Cambridge Dictionary）](https://dictionary.cambridge.org/dictionary/english/time-and-tide-wait-for-no-man) |
| 日が照るうちに、干し草を作れ。 | Make hay while the sun shines. | [英語のことわざ（Cambridge Dictionary）](https://dictionary.cambridge.org/dictionary/english/make-hay-while-the-sun-shines) |

日本語由来のことわざは含めていません。英語のことわざは作者を特定せず、辞書で定型表現を確認しています。「日が照るうちに、干し草を作れ」は、好機が続くうちに生かすという意味です。文学作品の引用は作品名・箇所を記し、登場人物の台詞を作者本人の発言とは扱いません。日本語訳は既存の翻訳から転載していません。
