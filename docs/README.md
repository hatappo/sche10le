## 資料の保管方針

- `docs/` は、現在の仕様・設計意図・再現手順・必要な検証結果を整理して参照できる資料の置き場とする。
- 一時的な比較案、試作HTML、検討中の画像やスクリーンショットは、原則として `/tmp/` またはGit管理外の `test-results/` に作成する。検討が終わったら残さない。
- 残す必要のある結論は既存の仕様書やデザインシステムへ統合する。「A案→B案」のような会話・試行の順序ではなく、採用した状態・理由・制約として記載する。変更履歴はGitで追える。
- デザインシステムの生成済みHTMLと、その原稿・テンプレート・UI見本は継続利用する資料として保持する。更新時は再生成と検証を行う。
- 公開中のバージョンに関する仕様や申告資料、未解決の実機検証に必要な情報は、一時資料と混同して削除しない。対象バージョンや未確認範囲を明記する。
- 資料を削除・統合するときは、参照リンクと生成スクリプトへの影響を確認する。
