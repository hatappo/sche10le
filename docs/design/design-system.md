# Sche10le デザインシステム

対象：拡張機能 0.6.0 開発版 / 記録日：2026-10-31

Chrome／Safari共通UIの実装を記録する。公開中の0.5.0のサイドパネルとは構成が異なる。公開前の実機検証・細部調整は `docs/dev/unified-0.6.0.md` を参照。

## 1. デザインの軸

静かな道具。ページの日程と内容を拾い、カレンダーへ渡すまでの連続性を優先する。説明や装飾を常設しすぎず、現在の操作と取得済みの内容が分かるようにする。

- ChromeとSafariは同じシート／ドロワーを使う。PCとモバイルで別の実装を持たない。
- 日程選択後は同じ領域が取得バーへ縮み、内容確認時に展開する。ページから取得する行動へ自然に誘導する。
- 太い枠・常設の光・過度な上下移動を避ける。新しい実行時依存と外部フォントを追加しない。

## 2. ブランドとアイコン

表記は製品名「Sche10le」、ワードマークは「sche10le.」。数字の10だけをイタリックにし、末尾のピリオドを黄土色にする。

| 要素                   | 現行値                                                        |
| ---------------------- | ------------------------------------------------------------- |
| ワードマーク原稿 | Georgia → Times New Roman → serif、600、20px / 1、字間 -1px |
| マークとロゴの間隔     | 7px                                                          |
| UI用のマーク       | 配布用32px PNGを24×24pxで表示                                        |
| PNG生成用マーク内の数字         | Georgia → serif、17px / 1、字間 -1px、右4px・下5pxの余白         |
| 虫眼鏡 | 上3px・左3px、直径21px・線幅1.4pxの円。柄は8×2px・45度 |

マークは日付を表すセリフ体の「10」に、検出を表す簡潔な虫眼鏡を重ねる。カレンダーの横線やリングは使わない。縦横比を変形したり、数字を別書体に差し替えたりしない。

配布用PNGは16・32・48・128px。マークの30:32の比率を維持し、高さをキャンバスの87.5%にして中央配置する。背景は透明。128px版はストアアイコンにも使用する。

`npm run icons` は`lib/brand.css`に保持した30×32px・角丸7pxのマーク原稿から描画する。Safari案内画面にも生成済みPNGを使用する。生成環境はGeorgiaを使用できるmacOSとPlaywrightのChromium。PNGを同梱するため、利用者の環境によって配布用アイコンの字体は変わらない。UI内の文字はOSのフォントに依存する。SafariのmacOSアイコン各サイズと案内画像も同時生成する。iOS用1024pxは深緑の不透明RGB背景とし、角丸はOSに任せる。プロモーション画像も同じCSSを参照する。

## 3. テーマと状態色

色の唯一の定義は `lib/theme.css`、名前とIDは `lib/themes.js`。UIの表示名は伝統色名、CSS・保存キーはASCIIにする。

| テーマ | ID | 用途 |
| --- | --- | --- |
| 千歳緑 | chitosemidori | 標準、紙色と深緑 |
| 銀鼠 | ginnezu | モノトーン |
| 水浅葱 | mizuasagi | 青寄りの水色 |
| 藍鉄 | aitetsu | 青系の暗色 |
| 黒茶 | kurocha | 茶系の暗色 |
| 紫紺 | shikon | 紫系の暗色 |

| トークン | 役割 |
| --- | --- |
| --paper / --ink | 基本背景と主文 |
| --surface / --line | 候補・補助操作の面と細い境界 |
| --accent | 現在の操作の文字と枠 |
| --complete / --muted | 完了した項目の淡い面と控えめな文字 |
| --action / --on-action | 最後のカレンダー主操作 |
| --bar-heading / --bar-on-heading | 案内帯の面と文字 |
| --error / --error-border | 入力・保存エラー |
| --focus | キーボードフォーカス |

通常の日程候補は白系の背景。取得中の項目は白系の面・アクセントの枠・太字で表現する。取得済みは淡い完了色・末尾のチェック。序数と項目名は同じ太さと色にする。再スキャン・選び直すは控えめな文字ボタンで、ホバーで下線を付ける。押せない操作は無効状態で領域を維持する。

カレンダー主操作だけは濃い面を使う。上部の案内帯は細長い領域として下段の操作面と色を分け、領域全体が巨大なボタンに見えるのを避ける。案内帯は上下ドラッグのハンドルを兼ねる。暗いテーマでも面・枠・本文・エラーをセットで切り替える。

## 4. 共通UI

- 狭い画面：幅は最大460px、左右12pxの余白。日時一覧は画面高の52%（最大520px）。確認・設定は72%（最大620px）。
- 幅760px以上：右側360px。日時一覧は最大560px、確認・設定は最大720px。画面からはみ出さない上限を併用。
- 取得バー：212px。選択した日時と「選び直す」、3項目と各取得内容の最大2行のプレビューを配置する。下段の操作リンクは置かず、右上の展開ボタンから途中でも確認画面へ進める。詳細の取得後は自動で確認画面へ移る。選択対象の文字はページ上で囲む。
- 上部の案内帯を上下移動でき、下端が初期位置。キーボードの矢印・Home・Endでも移動する。
- 確認画面：日時の横に「選び直す」、取得結果3行、カレンダー主操作とICSボタン。主操作下の補足文は置かない。
- 操作の配置：設定はヘッダの歯車、再スキャンは件数の隣。一覧・設定にはフッタを設けず、確認画面の主操作だけを下部に残す。設定の「戻る」は歯車と同じ右側の44px枠で切り替え、取得途中なら元の項目に戻る。
- プレビュー：タイトルは書式適用後、場所は現在値、詳細は本文と元ページURL。最大2行で末尾を省略し、URLのみの場合は中間を省略する。データ自体は短縮せず、確認画面と出力には全文を使う。
- テーマ選択：開閉できる選択欄に、日本語名・読み・背景／アクセント／文字の色見本を表示する。候補は2列で並べ、現在の選択にはチェックを添える。色見本は `data-theme-preview` と実際のCSS変数で描画し、画像や重複した色定義を追加しない。選択後は閉じて即座に反映する。
- 設定：移動時間 → タイトル書式 → カラーテーマ。3つの領域は背景や影を増やさず、間の1pxの罫線（--line）と上下20pxの余白で分ける。設定名は同じ位置・太さに揃える。入力・変数・プレビュー・初期値に戻す・書式例と説明はすべて書式の領域内に置き、自動保存の共通案内だけを領域外に置く。その下のことわざとの間も同じ罫線と20pxの余白で区切る。自動保存、書式プレビュー、変数挿入、保存失敗時だけ再試行。
- 見出し15px、本文14px、項目・補足12px程度。入力欄16px、主要な操作対象の高さ44px以上。OSの日本語フォントを使う。
- 閉じたShadow DOMでページCSSと分離し、色は拡張のホストにのみ設定する。元ページの配色を変えない。

## 5. 動き

高さの変形は320ms、cubic-bezier(.22,.61,.36,1)。別領域を突然出すのではなく、同じシートの状態を変える。

取得完了時は項目のラベルが850msで光り、チェックが残る。3項目完了時はカレンダーボタンを1.2秒で光が通過する。光が消えて10秒後に繰り返し、最大3回。操作を再開したら停止する。

再スキャン中だけ小さなスピナーを表示する。`prefers-reduced-motion` では変形・光・回転を省略する。状態の意味は色・チェック・文言でも残す。

## 6. ストア素材

`store/promotional/small-440x280.png`（440×280）と `marquee-1400x560.png`（1400×560）はRGB PNG。深緑の面、紙色の文字、黄土色の小さなアクセントを使う。アイコン・ロゴの印象は共通UIでも維持する。これらは実画面のスクリーンショットではない。

0.6.0の公開時は、実画面を示すストア用スクリーンショットをChrome／Safariそれぞれ更新する。AI補完やサイドパネルを現行機能として紹介しない。

## 7. 資料の更新

`lib/sheet.css` → UI見本、`lib/theme.css` → 配色、`lib/brand.css` → アイコン原稿。`docs/design/components.html` は表示用の見本であり、実際のページ読み取り・保存はしない。

`node scripts/build-design-system.js` でHTMLを再生成する。Markdown本文・画像・CSSを埋め込み、オフラインで閲覧できる。HTMLのコードブロックとダウンロードの内容はこのMarkdownと同一にする。`node scripts/check-design-system.js` で画像・状態切り替え・狭幅・ダウンロードを検証する。
