# Sche10le デザインシステム

対象：拡張機能 0.3.0 / 記録日：2026-10-27

この資料は、現在のUI・アイコン・ストア素材に実装されているデザインを記録する。数値は現行実装の値であり、すべてを共通トークン化したものではない。「方針」は今後の追加・修正時に守る判断基準を示す。

## 1. デザインの軸

ページの日程を見つけ、登録方法を選び、必要な文字をページから取得してGoogleカレンダーへ渡す。入力作業と往復を減らし、操作の連続性を優先する。

- 静かな道具：アイボリーと深緑、細い罫線、余白で区切る。装飾や説明を常設しすぎない。
- その場で理解できる：候補に触れると登録パターンが開く。対象の日時と取得先の項目を視覚的につなぐ。
- 次の一手を明確にする：濃い緑の大きな面は主操作に使う。選択中は黄土系、取得済みは淡い緑やチェックで区別する。
- 軽快さを守る：WXT・バニラJSを基本とし、描画やアニメーションのために実行時依存や外部フォントを追加しない。

## 2. ブランドとアイコン

表記は製品名「Sche10le」、ワードマークは「sche10le.」。数字の10だけをイタリックにし、末尾のピリオドを黄土色にする。

| 要素                   | 現行値                                                        |
| ---------------------- | ------------------------------------------------------------- |
| フッターのワードマーク | Georgia → Times New Roman → serif、600、20px / 1、字間 -1px |
| マークとロゴの間隔     | 7px                                                          |
| フッターのマーク       | 配布用32px PNGを24×24pxで表示                                        |
| PNG生成用マーク内の数字         | Georgia → serif、16px / 1、字間 -1px、上パディング6px         |
| PNG生成用マークの横線           | 上7px・左右6px、1px、白27%（#ffffff45）                       |

マークは上部の短い横線とセリフ体の「10」で構成する。以前のリング付きカレンダー風アイコンは使用しない。縦横比を変形したり、数字を別書体に差し替えたりしない。

配布用PNGは16・32・48・128px。マークの30:32の比率を維持し、高さをキャンバスの87.5%にして中央配置する。背景は透明。128px版はストアアイコンにも使用する。

`npm run icons` はサイドパネルCSSに保持した30×32px・角丸7pxのマーク原稿から描画する。フッターは生成済みPNGを使用する。生成環境はGeorgiaを使用できるmacOSとPlaywrightのChromium。PNGを同梱するため、利用者の環境によって配布用アイコンの字体は変わらない。UI内の文字はOSのフォントに依存する。

| UIの基本                 | 13px / 1.65                     |
| 手順のセクション見出し   | 12px・500（操作中は600）         |

| 日付バッジの日           | Georgia 28px / 0.95、字間 -1px  |
| 時間帯                   | Avenir系 14px / 1.7、字間 0.4px |
| 取得した内容             | 12px / 1.7                      |
| 主操作ボタン             | 15px・600 / 1.5                 |

## 6. サイドパネルの部品と状態

### 候補一覧

日程カードはホバーまたはフォーカスに応じて自動で開閉し、クリック・Enterによる手動の開閉切り替えは行わない。マウス由来のフォーカスが残っていても、ポインターがカード全体から離れれば閉じる。キーボードでは日程の案内からTabで登録方法へ進め、カード内にフォーカスがある間は開いたままにする。タッチではタップでフォーカスして開き、別の候補や操作へ移ると閉じる。閉じたときは元ページの強調表示も解除する。日程の案内はボタンではなく、フォーカス可能なグループとして表示する。

日付バッジ → 日程名・時間帯 → 出典の順に読む。ホバーとキーボードフォーカスで登録パターンを展開し、時間どおり・移動込み・終日を選べる。選択後は該当候補と取得内容に集中させる。「選び直す」で開いた候補と選択状態を解除する。

ローカルAIの候補だけに10pxの「AI」ラベルを置く（#fbf1dc背景・#785825文字、余白1×5px、角丸4px）。本文・構造化データの通常抽出にはラベルも空の出典行も置かない。詳しい出典と原文引用は日程へのホバーで表示し、スクリーンリーダーには抽出元を読み上げる。年を補った注記は日程の下に残す。

再スキャンは文字だけのリンク風ボタン。「選び直す」と同じ緑・11pxの通常ウェイトで、枠・背景・影を付けず、ホバー時に下線を表示する。実装はbuttonのまま、最小高さ36pxとキーボードのフォーカス表示を保つ。初回の「スキャン」と失敗後の「再試行」は淡い背景＋枠のボタンにする。実行中の「スキャン中…」は開始時のリンク風／ボタンの見た目を保って無効化し、先頭に11px・3秒で1回転のスピナーを表示する。待機中はスピナーを表示せず、動きを減らす設定では回転を止める。候補カードと同じ面積・外観にはしない。登場順／日時順は見出しのEnd側の控えめなselectで、独立した大きな設定行にしない。並び順は保存する。

### スキャンの状態

未許可のページではボタンと対象ページの情報帯を隠し、紙色と淡い緑の操作案内だけを表示する。案内タイトルは置かず、説明文の「Sche10le のアイコン」と「パズルのアイコン」の直後にそれぞれ画像を添える。画像は隣接する文章と同じ意味なので装飾として扱い、名称と離れて改行しない。エラー色は使わない。未スキャン・実行中は候補欄を空にし、日程の見出し・件数・並び順も隠す。完了後は0件でも見出し・件数・並び順を表示する。アクセス可能なら「スキャン」、実行中は無効な「スキャン中…」、完了後は「再スキャン」。対象外は専用の説明、一時的な失敗はエラー説明と「再試行」にする。0件の案内はスキャン完了時だけ表示する。

### AI補完の状態

「AIで日程を補完しています。表示されている候補は選べます。」の文頭に11pxのスピナーを置く。3秒でゆっくり1回転し、完了・失敗・無効化・ページ変更時に停止する。prefers-reduced-motionでは静止表示。状態はaria-liveで通知する。文中の「AIで日程を補完」などはホバー時だけ1pxの下線を表示し、キーボード操作時は共通のフォーカス枠を残す。押すと設定のAI項目へ移動してチェックボックスにフォーカスする。閉じると元のリンクへ戻る。無効化でリンクが非表示になった場合はフッターの設定ボタンへ戻る。

### 操作のセクション

「スキャン」「日時」「内容」の固定見出しで区切り、番号や進捗バーは置かない。見出しは12px・500・muted、操作中だけ600・greenとし、完了した見出しに10pxのチェックを付ける。チェック用の幅12pxは未完了時も確保し、位置を動かさない。未完了から完了へ切り替わったときだけ、見出しの文字内を淡い白金色の光が左から右へ550msで一度通る。文字の位置・大きさやチェックは動かさず、終了後は通常色に戻す。再描画・設定画面からの復帰では繰り返さず、prefers-reduced-motionでは省略する。スキャン結果はドメイン名と件数、日時の結果は選択済みカード、内容の結果は各取得欄に残す。完了のチェックはその工程を終えた意味であり、カレンダーへの保存完了は表さない。

スキャン欄は見出しとページ情報を左、スキャンボタンを右に置く2列のグリッドとする。件数はスキャン完了後だけページ名の横に表示し、日時欄には重複させない。「スキャン完了」の文字は読み上げ用に残し、画面では見出しのチェックで示す。日時の見出しはスキャン後から、内容の見出しと取得欄は日時選択後から表示する。未許可のページは従来のアイコン案内だけとする。

「選び直す」で日時が操作中へ戻り、取得欄を選び直すと内容のチェックが外れる。内容の項目をすべて選択またはスキップしたときは内容にもチェックを付ける。中断時も内容が現在の工程であり、再開操作を残す。読み上げには見出しの状態とaria-currentを使う。

### 取得中・取得済み

選択後の予定情報は選択済みカードに集約する。カードの元の日付・時刻の下に12pxの緑文字で「移動込み 13:30–16:30」のように登録内容を表示し、区切り線と9pxの上余白を置く。終日では「終日」とし、登録日が元の表示と異なる場合は日付も補う。時間付きの登録が日をまたぐ場合は両端の日付・時刻を明記し、仮の終了時刻の注記も維持する。カード下の「YOUR PLAN」や重複した日時は設けず、選択後も「日時」の見出しと選択済みカードを残す。Start側の見出しとチェック用の領域を固定し、End側（日本語UIでは右端）の操作は選択前の並び順から選択後の「選び直す」に切り替える。ヘッダの最小高さは30pxを維持する。カード下には取得結果だけを置く。登録内容に「登録：」という接頭辞は付けない。

サイドパネルはタイトル・場所・詳細の取得結果を表示する。行全体がクリック対象で、再選択できる。現在の対象は黄土系の背景・枠と項目名の太字（600）で示す。「選択中」のラベルは設けず、通常の項目名と取得本文は400のままにする。読み上げ向けのaria-currentと操作案内は維持する。ホバー／フォーカス時に編集アイコンを出す。取得・スキップで通過した項目には、ラベル横に10pxのチェックを残し、文字だけに工程見出しと同じ550msの光を一度通す。欄全体の発光や一時的なチェックは使わない。完了はdraft.stepより前の項目として導出し、選び直した手順以降はチェックを外す。再描画では光を繰り返さず、動きを減らす設定ではチェックのみ。読み上げ用の説明にも「設定済み」を添える。

タイトルの初期値はページタイトル、場所は空欄、詳細はページURL。詳細の取得後も元ページURLを末尾に空行で残す。書式を適用したタイトルと元の取得文字列を分けて保持する。取得手順を進める操作はページ下部に集約する。

### 主操作

「Googleカレンダーで開く」の隣に、40px四方・20pxのダウンロードSVGを持つ補助ボタンを8px間隔で中央揃えに配置する。背景は透明、枠はline、アイコンはgreen。ホバーでwash背景とgreen枠を付ける。title/aria-labelは「予定をダウンロード（.ics）」。狭い幅では主ボタンの文字を折り返し、両方の操作を表示する。

「Googleカレンダーで開く」をサイドパネル下部に固定する。文字は15px・600、最小高さ56px。取得途中でも進める。Googleカレンダー側で確認・保存するため、拡張内で保存完了を表示しない。

### 設定

移動時間欄の「次に選ぶ移動込みに適用」という補足は表示しない。タイトル書式の変数ボタンは、ホバーすると実際に挿入する文字列（`{title}`、`{from:HHmm}`、`{to:HHmm}`、`{date:YYYY-MM-DD}`）をブラウザ標準のツールチップで表示する。

設定を開くとメインの一覧とフッターを隠し、#eef1e8の専用面に切り替える。移動時間・タイトル書式・AI補完はすべて自動保存。個別の保存ボタンは設けない。有効な書式を即座にプレビューし、不正な書式は赤いエラー表示にする。保存失敗時には該当項目の「再試行」を表示する。

### フッターとブランド

Braveと判定でき、閉じるAPIに対応している場合だけ、設定の右に4pxの間隔で18pxの線画の×を表示する。クリック領域は設定と同じ36px以上、色とホバー面も共通とする。歯車と×はともに図形の中心をviewBoxの中央に置いたSVGとし、フォントの字形やベースラインによる上下のずれを防ぐ。titleとaria-labelは「サイドバーを閉じる」。閉じる失敗時はフッター内に赤字の通知を表示し、選択内容を維持して再試行できる。Chromeや判定失敗・API非対応の環境には追加しない。

左に24pxのアイコンと20pxのロゴ、右に20pxのSVG歯車アイコンだけの設定ボタンを1行で置く。操作領域は36px以上とし、ホバー時のtitleと読み上げ用のaria-labelに「設定」を指定する。ロゴにリンクや選択解除の動作は持たせない。予定選択中だけ、この行の12px上に主操作エリアを置く。本文下余白とルートのscroll-padding-bottomはResizeObserverで計測したフッター高＋16pxとし、取得結果行のscroll-margin-bottomは16px。設定表示中はフッターを隠すが、直前の高さを保持して復帰時のスクロールを安定させる。

主操作ボタン下の補足文は、取得途中は「情報の取得は途中でもOK。保存は Google カレンダーで。」、全項目の取得・スキップが完了したら「Google カレンダーで修正してから保存できます。」に切り替える。完了への切り替わりから650ms後、ボタンの輪郭に淡い緑の光を700msで一度だけ出して消す。項目ラベルの光と時間をずらし、ボタンの位置・大きさ・フォーカスは動かさない。再描画では繰り返さず、選び直し・設定表示・カレンダーを開く・ICS取得では中止する。動きを減らす設定では補足文だけを切り替える。

### 設定画面のことば

設定画面の最下部にだけ小さな緑の点＋日本語訳を置く。通常の候補一覧・取得中には表示しない。パネルを開くたびに海外の言葉6種から1つを選び、操作中は変えない。ホバーのtitle属性で英語原文と出典を示す。主操作と競合するサイズ・色にしない。

## 7. ページ上の取得オーバーレイ

ページと独立したclosed Shadow DOMに描画する。ページ本文のCSSで形や操作が崩れないようにする。

- 操作バー：幅640px、最大幅は画面幅−32px、下24px、余白12×16px、角丸14px。
- 上段：「ページ上の文字をクリック」と対象項目、右端に閉じるための「×」。×は16pxのSVGとし、32pxの操作領域を確保する。背景は透明、ホバー時だけ淡い面を表示する。ツールチップは「選択モードを閉じる（Esc）」、読み上げ名は「選択モードを閉じる」。
- 下段：タイトル／場所／詳細、戻る／スキップ。現在地は項目ボタンの番号・強調・チェックで示し、上段には「1 / 3」や完了チェックを重ねて表示しない。カレンダーを開くボタンは置かない。
- 選択中の項目：黄土系。取得済みの項目：淡い緑。操作可能な主ボタンの濃い緑と区別する。
- タイトル選択中の「戻る」、取得完了後の「スキップ」は無効状態で残す。詳細を選択中のスキップは可能。
- 取得完了後も操作バーを残し、前の項目へ戻れる。右上の「×」とEscは全段階で取得内容を保持してページの通常操作に戻る。
- 560px以下は下段を2行にし、340px以下は余白・文字を縮める。手順の変化でボタン位置やバー全体の寸法が跳ねない。

オーバーレイ専用色は基本背景#f9f8f2、文字#243e32、境界#b18a46。候補の元文字列は黄土系の縁と波紋で示し、それ以外のページを#19231f・48%で暗くする。ページのクリックを妨げない。

| ボタンの色・押下         | 140ms、押下時に下1px         |
| 候補の境界・影           | 160ms                        |
| 登録パターンの開閉・矢印 | 180ms                        |
| 候補の出現               | 220ms、下4pxから現れる       |
| 取得セクションの出現     | 200ms                        |
| 元の日時への追従開始     | ホバー／フォーカス後 約180ms |
| 元文字列の波紋           | 1.1秒×3回                    |
| 取得バーの開始・再開     | 850ms、背景と光の縁          |
| ページ上の選択枠の追従   | 70ms                         |
| 内容の項目ラベルの光     | 550ms、完了への切り替わり時に1回 |
| 工程見出しの光           | 550ms、完了への切り替わり時に1回 |
| 完了後の主操作の光       | 650ms待機後、700msで1回       |
| スキャン中の小さな点     | 1秒周期、処理中のみ          |

動きは、原因と結果・対象位置・完了状態を知らせるために使う。飾りの常時アニメーションは追加しない。prefers-reduced-motionでは移動・パルス・画面遷移の動きを抑え、文字や静的なチェックを残す。

## 9. 操作とライティングの方針

- 色だけに依存せず、項目名の太字・エラー理由・チェック・disabled状態を併用する。
- ボタン全体をクリック可能にする。キーボードで候補を展開し、行の再選択はEnter／Spaceでも行える。
- フォーカス：サイドパネルは黄土色2px・offset 4px。取得バーは3px・offset 2px。
- スキャンと再スキャンで語彙を統一する。「走査」と混在させない。
- 選択モードを閉じる操作は段階によって意味や読み上げ名を変えない。「連携完了」「保存完了」といった、実際に確認できない完了表現は使わない。
- 触れば分かる機能に説明文を重ねない。常設ヒーローコピーを拡張の狭いUIに置かない。
- 設定を閉じたら元の操作へ戻る。不要な確認ダイアログで操作を止めない。
- 日付の選択・文字の取得・カレンダーへの移動という主導線を優先し、将来のサービス追加でも主ボタンを横並びに増やさない。

## 10. プロモーション素材

UIと同じ紙色・深緑・Georgiaのワードマークを使用する。背景は少し深い#214b37。黄土系#d2b477の矢印とピリオドで、読み取りからカレンダーへ渡す方向を示す。

| 素材     | 仕様                                      | 主な組版                       |
| -------- | ----------------------------------------- | ------------------------------ |
| 小タイル | 440×280px、24ビットRGB PNG、アルファなし  | ロゴ36px、見出し20px、補足10px |
| マーキー | 1400×560px、24ビットRGB PNG、アルファなし | ロゴ64px、見出し43px、補足16px |

コピーは「ページの日程を、カレンダーへ。」、補足は「Googleカレンダー対応」。見出しの行間は小1.75／大1.65。素材は単純拡大ではなく、キャンバスごとに余白・配置・文字サイズを調整する。切れた文字や過剰な小文字を避け、縮小時もブランドと用途が伝わるようにする。

ページとカレンダーの図は機能を説明するイラストであり、実際の製品画面のスクリーンショットではない。ストアのスクリーンショット欄には実画面を使用する。プロモーション画像はZIPに同梱しない。

## 12. 更新時の確認

1. 実装CSS・アイコン・プロモーション・本資料で色と字体の意図が揃っているか確認する。
2. 280〜320pxの狭い幅、キーボードフォーカス、長いタイトル・URLを確認する。
3. 選択中・完了・操作可能・無効・エラーが判別できるか確認する。
4. 動きを減らす設定で、意味や完了の通知が失われないか確認する。
5. PNGの寸法とアルファの有無を検証する。アイコンは透明可、タイルはRGB・アルファなし。
6. HTMLを再生成し、コードブロック・ダウンロードしたMarkdown・原稿の内容が一致するか確認する。

HTMLのUI見本は実装CSSを使った資料用デモ。ページの読み取り、設定の永続保存、Googleカレンダーへの移動は行わない。資料専用の見出しやナビゲーションの大きさは、拡張本体の新しいトークンではない。
