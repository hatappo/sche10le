# Safari実機確認（0.6.0）

## 最初の接続

1. iPhoneまたはiPadをUSBでMacへ接続し、端末のロックを解除する。
2. 端末に「このコンピュータを信頼しますか」と出たら、自分の開発用Macであることを確認して信頼する。
3. `native/safari/Sche10le.xcodeproj` をXcodeで開き、Schemeを **Sche10le (iOS)**、実行先を接続した実機にする。
4. 開発者モードを求められたら、端末の「設定」→「プライバシーとセキュリティ」→「デベロッパモード」をオンにし、画面の案内に従って再起動・確認する。表示されない場合は先にXcodeで端末を接続・ペアリングする。
5. Xcodeの **Settings → Apple Accounts** で開発に使うApple Accountを確認し、アプリと拡張の両ターゲットに同じTeamを設定する。個人の署名設定は `native/safari/Config/Signing.local.xcconfig` に分離する（[手順](../../native/safari/README.md#署名とbundle-identifier)）。アカウント追加・規約への同意・登録が必要なら、本人が画面で操作する。
6. `npm run prepare:safari` の後、XcodeのRunで起動する。`build:safari:ios` は署名なしのシミュレーター用なので、実機インストールには使わない。

Teamや証明書がまだ用意できていない場合は、Xcodeのエラーを確認してから対処する。署名の解決のためにリポジトリの権限を増やしたり、証明書・秘密鍵をコミットしたりしない。

- [Apple：実機・シミュレーターでの実行](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices)
- [Apple：デベロッパモード](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device)

## Safariからの起動

案内アプリに表示される2つの手順を実施する。

- iPhone/iPad：設定→アプリ→Safari→機能拡張でSche10leをオンにする。iOS 17では「アプリ」を挟まず、設定→Safariへ進む。日程のあるページをSafariで開き、検索フィールドのページメニューからSche10leを選ぶ。
- Mac：Safariの設定→機能拡張でSche10leを有効にする。案内アプリのボタンから設定を開ける。日程のあるページを開き、ツールバーのSche10leアイコンから起動する。設定から案内アプリへ戻ると、有効・無効の状態を再取得する。

Safariの表示はOSやツールバーの構成で異なる。案内図は操作場所の目安であり、スクリーンショットの完全な再現ではない。iOSの有効状態を推測してチェック済みにはしない。

実機で `127.0.0.1:4175` を開いてもMacの検証サーバーには接続できない。まず普段使う公開イベントページなど、表示日時を目視できるページで確認する。ローカルサーバーは引き続き127.0.0.1だけで待ち受ける。

- [Apple：iPhoneの機能拡張](https://support.apple.com/ja-jp/guide/iphone/iphab0432bf6/ios)
- [Apple：Macの機能拡張](https://support.apple.com/ja-jp/102343)

## 操作と期待結果

| 操作 | 確認すること |
| --- | --- |
| 初回起動・アクセス許可／拒否 | 許可したページで起動する。拒否時に誤って成功扱いせず、案内が表示される |
| 日時選択 | ページの日時と候補が一致する。強調箇所が読め、日時選択後に取得バーへ縮む |
| タイトル・場所・詳細の取得 | タップで選択できる。スクロールを誤取得しない。選択した値がプレビューへ反映される |
| 長押しでの範囲取得 | 選択ハンドルを調整しても項目が進まない。項目ボタンに仮表示し、解除すると元に戻る。範囲の近く／バー内の「この範囲を使う」で選んだ文字だけを取得する。選択メニュー・スクロールとの干渉、リンク内・複数段落の選択も確認する |
| 候補の目印 | ソート、ページ上の強調表示、日時選択後も同じA・B・Cが表示される |
| 取得中の設定・途中確認・選び直し | 設定から元の取得位置へ戻る。途中確認では内容を保持し、日時の選び直しではリセットする |
| 横向き・キーボード・ページ末尾 | バーが画面外へ出ず、設定を操作できる。必要ならドラッグで対象を露出できる |
| Googleカレンダー | 正しい日時・書式・場所・詳細で予定作成画面が開く。予定の保存操作は確認者が判断する |
| ICS | ダウンロード・共有／保存・カレンダーへの取り込みで内容が一致する。意図せず重複登録しない |
| 閉じる・再起動・ページ遷移 | 同じページでは内容が残る。再読み込みや別URLでは前の内容を持ち越さない |
| 文字拡大・VoiceOver | 案内の最後まで読める。項目名とボタンの役割、現在地が分かる |
