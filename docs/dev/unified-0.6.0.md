# Safari／Chrome 統合版 0.6.0

2026-10-30 決定。0.6.0を両ブラウザの共通UI版として目指す。現時点では開発版であり、タグ・ストア提出・Safari配布は未実施。

## 方針

- Chromeのサイドパネルを廃止し、Safariと同じページ内シート／ドロワーへ統一する。旧UIとの切り替え設定は設けない。
- 狭い画面では下部シート、広い画面では右側ドロワー。同じDOM・状態遷移・設定を使い、CSSと利用可能な画面領域でレイアウトを変える。
- 日時選択 → 取得バーへの縮小 → 内容確認への展開を共通にする。PC／スマホそれぞれのUI実装を増やさない。
- AI補完は設定・実行処理とも一旦撤去。通常スキャンは維持し、安定後にChrome限定の再導入を検討する。
- activeTab・scripting・storageのみを使う。常時読み取り・広域ホスト権限は追加しない。
- Chromeは既存の拡張ID／ストア掲載を更新し、Safariは新規のネイティブ配布を準備する。両方のコードバージョンを0.6.0に揃える。審査完了日が同日になることは前提にしない。

## 実装の境界

| ファイル | 役割 |
| --- | --- |
| `entrypoints/background.js`、`lib/extension-background.js` | 起動したタブのUIを再表示。未注入時だけスクリプトを注入。Googleカレンダーへの受け渡し |
| `entrypoints/sheet.content.js` | 二重起動防止、ページ遷移、拡張ストレージの接続 |
| `lib/sheet.js` | 共通シートの組み立て、候補・取得内容の描画、スキャン・保存・カレンダーへの受け渡し |
| `lib/sheet-state.js` | 日時選択・項目取得・確認・設定・閉じる・リセットの状態遷移。DOMや拡張APIに依存しない |
| `lib/sheet-settings.js` | 設定画面の入力・検証・プレビュー。保存は呼び出し元へ通知 |
| `lib/sheet-interactions.js` | ページ上の取得、スクロールとタップの区別、ドラッグ、Visual Viewportへの追従 |
| `lib/sheet-elements.js`、`lib/theme-selector.js` | DOM部品。ブラウザごとの複製を作らない |
| `lib/sheet.css`、`lib/theme.css` | 共通スタイル、画面幅・テーマへの対応 |
| `lib/preferences.js` | 0.5から維持する設定キー・検証・標準値 |
| `lib/extract.js`、`calendar.js`、`ical.js` など | 日程抽出・予定生成。ブラウザに依存しない |
| `lib/source-highlight.js` | 出典の強調とシートを考慮したスクロール |
| `entrypoints/help/` | 注入できないページでの案内 |
| `native/safari/`、`scripts/prepare-safari.js` | Git管理するXcodeプロジェクト、共有Scheme、Web生成物の参照・バージョン同期。署名設定はローカルへ分離 |

ページの本文・候補・取得内容はそのページのContent Script内のメモリーに置く。閉じても残し、再読み込み・別URLへの遷移で破棄する。バックグラウンドの存続に依存させない。初回起動／再スキャン以外は本文を自動スキャンしない。

設定キー（`travelMinutes`、`titleFormat`、`candidateOrder`、`themeId`）は変更しない。設定は各ブラウザ・プロファイルの拡張専用 `browser.storage.local` に保存する（クラウド同期なし）。バックグラウンド起動時に廃止キー `aiEnabled` だけを削除する。更新後にも実行され、失敗時は次の背景起動で再試行。現在の4キーや未知のキーは削除しない。モデルにはアクセスしない。設定の連続保存は直列化し、保存失敗時は表示を維持して再試行する。

## 状態遷移の保守ルール

`sheet-state.js` の `transitionSheet` が、画面・戻り先・選択した日時・取得内容・完了チェックをまとめて更新する。描画やイベント側からこれらを個別に書き換えない。新しい遷移はここへ追加し、利用シナリオを `tests/sheet-state.test.js` で検証する。

- 日時選択で新しい下書きを作り、タイトル取得へ進む。
- 項目を取得するとその項目だけ完了にし、次へ進む。詳細の取得で確認画面へ進む。
- 項目の移動や途中確認だけでは完了扱いにしない。取得済み項目を選び直しても、他の値と完了チェックは残す。
- 設定は直前の画面と取得位置を記憶する。設定を閉じて再表示しても、戻る先を保持する。
- 取得中に拡張を閉じると、内容を保持して確認画面へ移る。表示／非表示はDOM側で管理する。
- 日時の選び直し・再スキャン・ページ遷移では、下書きと完了チェックを初期化する。設定は別に保持する。

DOM、タイマー、非同期処理の世代管理、保存キューは `sheet.js` に残す。入力イベントは `sheet-interactions.js` が登録し、Content Script破棄時の共通AbortSignalで解除する。ブラウザ名ではなく画面幅・入力方法・Visual Viewportに応じて対応する。

## 検証の分担

- `npm run check`: lint・型・抽出／書式／ICS／設定などの単体テスト・Chromeビルド。
- `npm run test:e2e`: Chromeの実拡張。設定引き継ぎ、URL/ICS、再表示・二重注入、別タブ、ドラッグ、ライブ検証ハーネスのローカル回帰。
- `npm run test:ui`: 共通UIをChromiumとWebKitで検証。タッチ、設定エラー／再試行、6テーマ、狭幅、完了・項目移動・選び直し、フォーム除外、reduced motion。
- 旧サイドパネル／AI専用のE2Eは削除し、共通の利用シナリオへ移行する。ライブ検証は本番ビルドの共通Content Scriptを使い続ける。
- テスト用コピーのみ一時的に対象ホスト権限を付け、閉じたShadow DOMを観測可能にする。配布用には含めない。ツールバー操作によるactiveTab許可は手動検証が必要。

## 範囲取得と候補の目印

`sheet-interactions.js` はブラウザ標準のSelectionを使用する。クリック／タップによる領域取得に加え、マウスドラッグは終了時に範囲を取得し、タッチでの範囲選択は「この範囲を使う」で明示確定する。`selectionchange` で状態遷移は行わず、プレビューのみ更新する。現在の項目ボタンにも `pickField` のコピーと既存の書式処理を使って仮表示し、確定前の下書きは保持する。確定ボタンはバー内と選択範囲の上下に共通の処理で提供する。近接ボタンは上下を独立に判定し、画面・取得バー・選択範囲と重ならない側だけ表示し、配置計算は選択中のRange（80矩形まで）に限定、スクロール／VisualViewport更新をrequestAnimationFrameにまとめる。取得・項目移動・設定・閉じる時に保留範囲を解放する。入力欄や編集可能領域、別フレーム、拡張自身を範囲の取得元にしない。ページの `user-select` や長押しメニューは変更しない。

候補の目印は重複除外後の登場順にA〜Z、AA〜と割り当て、スキャン中の対応表をUIが保持する。並び順や登録方法を変えても変化せず、予定タイトルやICSには混入しない。元の文字列を特定できない構造化データにはページ上の目印を表示しない。強調の目印は既存の描画更新に合わせて移動し、スクロール時に本文を再走査しない。

自動テストでは実際のマウスドラッグとSelection APIを使った範囲変更・タップ確定を検証する。iPhoneの長押し・ネイティブ選択ハンドル・メニューはPlaywrightのWebKitだけでは保証できないため、実機確認を別に記録する。
