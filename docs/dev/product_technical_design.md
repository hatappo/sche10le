# 製品・技術設計書: Sche10le

Sche10le（スケジュール）は、Webページの日程候補を抽出し、選んだ登録パターンでGoogleカレンダーの予定作成画面を開くChrome拡張。

## 1. 製品方針

日程の転記を減らし、「気になる日を、予定にする」までの操作を短くする。対象は勉強会・展示会・ライブ・セミナーなどをWebで探す人。

- 拡張内に予定の編集フォームを設けない。修正と保存はGoogleカレンダーに任せる。
- 入力させる代わりに、日程候補と登録パターンを選べるようにする。
- タイトル・場所・詳細を推測しない。必要な情報はページ上でクリックして拾う。
- AIがなくても基本機能が成立する。機械的な候補を先に操作できる。
- 「Googleカレンダーで開く」と表示し、保存前に「登録済み」とは表示しない。

## 2. 操作フロー

1. 拡張アイコンからサイドパネルを開き、現在のページをスキャンする。
2. 日程候補を一覧表示する。ホバー・フォーカス・クリックで登録パターンを展開する。
3. パターンを選ぶと、自動的にページからの取得モードを開始する。
4. タイトル → 場所 → 詳細の順にページ上の文字をクリックして取得する。
5. 各項目はスキップ可能。戻る・一時停止・再開・日程の選び直しもできる。戻る・スキップ・項目切り替えの専用ボタンはページ下部の操作バーだけに置き、使えない操作はdisabled状態で残す。タイトル選択中は「戻る」を無効にし、詳細の取得中までは「スキップ」を有効にし、取得完了後は無効にする。
6. 全段階でサイドパネル下部に「Googleカレンダーで開く」を表示し、途中でも現在の内容で進める。ページ下部の操作バーには同じボタンを置かず、項目の選択・戻る・スキップ・閉じる操作に役割を絞る。サイドパネルの主操作は15px・太字の文字と56px以上の高さで目立たせる。
7. Googleカレンダーの予定作成画面を別タブで開く。最終保存はユーザーが行う。

操作バーは上段に「ページ上の文字をクリック」と取得先項目、下段に項目切り替えと操作を置く。現在地は項目名の太字・枠・末尾のチェックで表し、上段の「1 / 3」や完了チェックは設けない。幅と各ボタンの領域を固定し、狭い画面では下段を2行にする。取得中の手順変更では大きさ・ボタン位置を維持し、3項目完了時は閉じる。開始・再開時は1600msで領域全体を柔らかい光が一度横切り、項目切り替えでは再生しない。これによりモード変更を知らせ、動きを減らす設定では動かさず案内文で伝える。操作バー右上には32pxの操作領域に16pxのSVGの「×」を置き、下段の「戻る」「スキップ」から分離する。全段階で取得内容を残して本文の通常操作に戻り、Escでも同じ動作にする。ツールチップは「選択モードを閉じる（Esc）」、読み上げ名は「選択モードを閉じる」とする。

3項目の取得・スキップが完了したら、ページ下部の操作バーと選択枠を閉じ、本文の通常操作に戻す。サイドパネルの項目をクリックまたはEnter／Spaceで選び直すと操作バーを再表示する。完了だけでは一時停止扱いにせず、再開ボタンは表示しない。操作バーは現在の項目を白背景・深緑の枠・太字、通過済みの項目を淡緑と項目名の後ろのチェックで表す。サイドパネルと同じ序数（1・2・3）を項目名の前に付け、完了後も残す。内側シャドウは置かず、未完了は番号と項目名、完了後は末尾のチェックも含めて中央寄せする。項目ボタン全体は幅320pxとし、狭い画面では利用可能な幅を使う。選択済みの日程カードは淡緑の背景にし、日時見出しのチェックとカードの表示で確定を示す。サイドパネルは取得結果の行を白背景・深緑の枠と項目名の太字（600）で強調し、専用の3項目切り替え・戻る・スキップ・操作案内枠を置かない。取得結果の行全体をネイティブbuttonとし、クリックやEnter／Spaceから項目の選び直しを開始できる。ホバー・キーボードフォーカス時に編集アイコンを表示し、取得内容は読み上げ用の説明にも関連付ける。進行状況はライブ領域で読み上げる。中断後の再開ボタンはサイドパネルに残す。濃い緑の塗りは「Googleカレンダーで開く」の主操作に使う。取得またはスキップで通過した項目は淡緑の背景と全周の薄い枠にし、影を付けず、ラベル横に静的なチェックを残し、文字だけに550msの完了エフェクトを一度表示する。完了状態はdraft.stepより前の項目として導出し、選び直すとその手順以降のチェックを外す。欄全体の発光と一時的なチェックは使わない。動きを減らす設定では静的なチェックだけにする。

全項目の取得・スキップ完了時は、フッタの補足文を「情報の取得は途中でもOK。保存は Google カレンダーで。」から「Google カレンダーで修正してから保存できます。」へ切り替える。完了から650ms後に主操作ボタンの表面を柔らかい光が1300msかけて一度流れ、輪郭も光らせる。光が消えてから10秒の間隔で追加2回まで繰り返し、再描画では回数や待機時間をリセットしない。ボタンの位置・大きさとフォーカスは維持する。選び直し・設定表示・カレンダーを開く・ICS取得で演出を中止し、動きを減らす設定では省略する。

「選び直す」では全候補の選択・展開・出典強調を解除し、一覧見出しにフォーカスを戻す。候補へ再びホバーまたはフォーカスするまでニュートラルな一覧を保つ。

サイドパネルには候補・進行・取得結果を表示する。ページには対象のハイライトと小さな案内バーを重ねる。中央ダイアログで本文を隠さない。取得中のリンククリックは移動を抑止し、入力欄は取得対象外とする。パネル終了、タブ変更、ページ遷移で選択UIとイベントリスナーを解除する。

候補のホバー・フォーカスが180ms続いたら、出典文字列までスクロールし、文字列の範囲を3回のパルスで強調し、その周囲以外を暗くする。SVGマスクで各行の範囲をくり抜き、最低32pxの高さと余白を確保する。マスクの重なりで暗くならないようにし、画面外の対象へスクロール中は対象が見えるまで暗転しない。オーバーレイはポインター操作を妨げない。候補離脱・パターン選択・接続終了で解除する。動きを減らす設定では即座のスクロールと静的強調にする。出典を特定できない候補ではページを動かさない。

候補見出しのチェック領域から16px空けたStart側に小さなネイティブselectで「登場順／日時順」を置き、切り替え用の行は増やさない。初期値は本文の登場順。引用と出現回数から本文の位置を求め、構造化データを優先して統合した候補も本文の位置へ戻す。位置不明の候補は末尾に抽出順で並べる。日時順は開始日・開始時刻の昇順、同日の終日は先頭、同日時は登場順とする。選択値は`chrome.storage.local`の`candidateOrder`に自動保存し、再スキャン・選び直し・パネルの開閉後も維持する。未保存・不正値・読込失敗時のみ登場順を使う。保存は他の設定と同じキューで直列化し、保存失敗時のみ一覧に赤い案内と再試行を表示する。AI補完では選択した順序に挿入し、既存カードとフォーカスを保つ。候補が2件未満またはスキャン中は切り替えを無効化する。対象ページと再スキャンは下線で区切る情報帯にまとめる。ページ情報はドメインとスキャン結果の件数に絞り、完了は見出しのチェックで示し、タイトルはドメインのtitle属性で確認できるようにする。再スキャンはアイコンと文字、枠と薄い背景色を持つ36px以上の高さのボタンで操作を明示する。

ヘッダを設けず、固定フッタの下段に小さなロゴと歯車アイコンの設定ボタンを配置する。設定ボタンはアイコン20px、操作領域36px以上とし、titleとaria-labelに「設定」を指定する。ロゴは非操作要素とし、選択を解除しない。予定選択中だけ上段に主操作ボタンと補足を表示する。ResizeObserverでフッタの実高を計測し、本文下余白とスクロール時の見切れ防止に反映する。設定画面は全高の専用面とし、その最下部に小さな点を添えて名言を表示する。同梱した6つの海外のことわざ・文学作品の言葉から起動時に1つをランダムに選ぶ。操作中・再スキャン時は変えず、タイマーや通信、保存処理は追加しない。通常は日本語の独自訳を表示し、ホバー時に英語原文と出典を表示する。日本語由来のことわざは含めない。原文・出典URLは各データに保持し、全訳文・英語原文・参照先はREADME末尾の折りたたみに記載する。候補一覧下の「日程に触れると、登録方法を選べます。」は表示しない。

画面を「スキャン」「日時」「内容」の固定見出しで区切る。既存のscanState・draft・draft.stepから操作中／完了を導き、別の進捗状態は保存しない。見出しは12pxで、操作中は600・green、完了は500・mutedと小さなチェック。aria-currentと読み上げ用の状態文も更新する。スキャンの完了結果はページ名と候補件数、日時の結果は選択済みカード、内容の結果は取得欄で確認できる。日時はスキャン後、内容は日時選択後だけ表示し、未許可時の案内はそのまま維持する。日程の選び直し・内容の再取得・再スキャン・ページ変更で進行表示も戻る。スキップを含めて内容の取得手順を終えると全見出しにチェックが付くが、カレンダーへの保存完了は表さない。

### 2.1 登録パターン

| パターン   | 内容                                   |
| ---------- | -------------------------------------- |
| 時間どおり | 抽出された開始〜終了時刻               |
| 移動込み   | 開始前・終了後にそれぞれ移動時間を確保 |
| 終日 | 該当日または日付範囲の終日予定         |

移動時間は前後それぞれ30分を初期値とし、設定で0〜180分の整数に変更できる。入力欄の矢印は5分刻み、直接入力は従来どおり0〜180分の整数を受け付ける。0分なら移動込みを省く。移動込みの詳細には元の開催日時も残す。設定変更は次に選ぶパターンから反映し、選択済みの予定を勝手に変えない。

ホバー前の一覧では、時刻付き候補と開始日・終了日が一致する終日候補を、出現順に関係なく除外する。同じ範囲の終日候補同士も1つにまとめる。各時刻付き候補の時間どおり・移動込み・終日はすべて維持する。単日と複数日など、日付範囲が異なるものは統合しない。件数表示は一覧に合わせる。AI補完時は残るカードのDOMとフォーカスを維持し、不要になった終日カードだけを除く。予定を選択済みなら選択と取得内容を維持し、一覧に戻るまで候補の表示更新を延期する。

時刻のない候補は終日のみ。開始だけ判明している場合は終了を1時間後とするが、仮の終了時刻であることを選択肢とプレビューに明示する。

選択後は元の日付・時刻が見える候補カードに「移動込み 13:30–16:30」のような短い登録内容を添え、重複する見出し・日時をカード外に表示しない。登録が日をまたぐ場合は両端の日付を明記する。終日の日付範囲が元の表示と異なる場合も登録範囲を補う。選択後も「日時」の見出しを残し、Start側の並び順を隠し、End側に「選び直す」を置く。チェック領域は未完了時も12pxを確保し、並び順や選び直すと同じ場所に出さない。件数はスキャン欄のページ名の横へ表示する。選び直すと元の一覧と並び順を復元する。登録内容には「登録：」を付けない。

### 2.2 初期値と取得

| 項目     | 初期値            | ページから取得した場合   |
| -------- | ----------------- | ------------------------ |
| タイトル | `document.title`  | 選択テキストで置き換える |
| 場所     | 空                | 選択テキストで置き換える |
| 詳細     | 取得元ページのURL | 選択テキスト＋空行＋URL  |

取得した詳細と元ページURLは別々に保持し、受け渡し時に結合する。選び直してもURLを消さず、末尾に1回残す。移動込みでは「選択テキスト → 開催日時 → 元ページURL」の順に空行で区切る。

### 2.3 タイトル書式

初期値は `{title}`。設定で固定文字と変数を組み合わせられる。元のタイトルと書式を分けて保持し、サイドパネルのプレビューとカレンダーURL生成時に同じ関数で書式を適用する。タイトルを再取得しても書式は維持され、装飾を二重に適用しない。有効な入力は選択中の予定へ即時反映し、自動保存する。保存処理を直列化し、入力順を維持する。無効な入力は赤いエラー枠・明示的な見出しで知らせ、最後に適用できた書式を使う。保存失敗も赤字で表示し、エラー時のみ表示する共通の「再試行」ボタンから再保存できる。

- `{title}`: ページタイトルまたは取得テキスト。
- `{from:HHmm}` / `{to:HHmm}`: 移動時間を含まない元の開催開始・終了時刻。`HH:mm`も対応。`hhmm`は24時間表記の別名として受け付ける。形式省略は`HH:mm`。
- `{date:YYYY-MM-DD}`: 登録する予定の開始日。`YYYY/MM/DD`、`MM/DD`、`M/D`も対応。形式省略は`YYYY-MM-DD`。
- 移動込みでも時刻変数は元の開催時刻を使う。カレンダーに渡す時間帯は移動を含める。日付変数は従来どおり登録する予定の開始日（移動で前日にまたがる場合は前日）。終日の時刻変数は空文字。固定の文字や記号はそのまま残す。
- 200文字以内の1行。未対応の変数・書式・不正な括弧は保存を拒否する。コードとして評価しない。
- 変数の挿入ボタンとライブプレビューを設ける。

### 2.4 設定画面

設定表示中は日程一覧と登録フッターを隠し、背景を変えた専用画面に切り替える。移動時間・書式・AI補完を枠付きの項目として分ける。「変更は自動保存されます」を画面先頭に表示し、通常の保存ボタンは設けない。3項目は共通の保存処理・保存中／保存済み／エラー表示を使用し、保存失敗時だけ「再試行」を表示する。保存は直列化し、古い結果が新しい編集の状態表示を上書きしないようにする。不正入力は反映も保存もせず、最後の有効値を維持する。「閉じる」またはEscで元のスクロール位置と予定の選択状態を保って戻る。

## 3. 技術構成

- **WXT / Manifest V3**。JavaScriptのES Modulesを使用し、JSDocとTypeScriptの`checkJs`で型検査する。
- **バニラHTML/CSS/JS**。実行時の追加パッケージはゼロ。アニメーションはCSS中心。
- **Content Script**: ユーザー操作時だけ注入。本文とJSON-LDの取得、ページ上の選択を担当する。
- **Side Panel**: 抽出・候補・登録パターン・取得状態・カレンダーURL生成・任意のAI処理を担当する。
- **Background Service Worker**: 拡張アイコンからサイドパネルを開く。常時スキャンは行わない。
- **接続**: サイドパネルからContent ScriptへPortを接続。切断時に選択UIを解除する。スキャン世代と取得ステップごとのトークンで古い結果を破棄する。

### 3.1 権限

`activeTab`、`scripting`、`sidePanel`、`storage` のみ。全サイトへのホスト権限、常時実行Content Script、`tabs` 権限は要求しない。

拡張アイコンのクリックで一時的なアクセス権限を取得する。タブ・ページ切替では本文やDOMを参照しない `() => true` の注入だけでアクセス可否を確認し、自動スキャンはしない。同一オリジン内の移動や許可済みタブへの復帰では既存権限を利用できる。未許可ならスキャンボタンと対象ページの情報帯を隠し、上部にアイコン操作の案内だけを通常色で表示する。案内タイトルは置かず、本文中の「Sche10le のアイコン」「パズルのアイコン」の直後に装飾アイコンを配置する。アクセス可能な未スキャン状態は「スキャン」、実行中は無効な「スキャン中…」、完了後は「再スキャン」。Chrome内部ページやWeb Storeなど既知の対象外ページには専用の案内を表示し、一時的な接続失敗はエラー説明と「再試行」にする。失敗を一律に権限不足と判定しない。未スキャンと実行中の候補欄は空にし、「日時」の見出し・件数・並び順・並び順の保存エラーも非表示にする。完了後は0件でも見出し・件数・並び順を表示し、0件の場合だけ空結果の案内を表示する。非同期のアクセス確認にもスキャン世代番号を適用し、古いタブの結果を無視する。追加権限は要求せず、サイドパネルのボタン操作そのものは `activeTab` を付与しない。

### 3.2 機械的抽出

1. JSON-LDのEvent系オブジェクトを解析する。配列、`@graph`、複数の`@type`を扱う。
2. 本文から日本語・スラッシュ・ISO形式・令和・英語月名の日付と近傍の時間帯を抽出する。
3. 同一の日時を重複排除し、構造化データを優先する。本文から得た出典位置情報は統合後も保持する。

出典の強調には、空白・全角表記を正規化した引用と出現回数を使う。スキャン時に可視テキストノードとDOM位置の対応を上限付き（20,000ノード・100,000文字）で保持し、候補ホバーごとの全文スキャンは避ける。表示直前に元の文字列が変わっていないことを確認する。ページの本文要素は書き換えず、Shadow DOMのオーバーレイでDOM Rangeの矩形を強調する。

- 年も時刻もない単独の月日は本文抽出から除外する（`2/3`、`11月8日`、`Nov 8`など）。年付きの終日、年省略の時刻付き、両端に月日がある期間は残す。JSON-LDの終日イベントは維持する。
- 年省略はスキャン時の年とし、候補に明示する。勝手に翌年に送らない。
- 終了時刻が開始時刻より前なら翌日として扱う。
- 終日の範囲の最終日は包含する。カレンダーへ渡す際に翌日の排他的終了へ変換する。
- タイムゾーンが不明な日時は端末のタイムゾーン。JSON-LDの明示オフセットは保持し、表示を端末のタイムゾーンに合わせる。
- 不正な日付・時刻、矛盾する終了日時は除外する。
- 本文は最大100,000文字、候補は最大100件。JSON-LDは件数・サイズ・深さ・ノード数を制限する。
- 全角の数字・記号はNFKCで正規化してから抽出する。
- 令和は数字年または元年に対応し、2018＋年数で換算する。2019-05-01より前・0年・実在しない日付を拒否する。本文は置換せず、元の文字範囲を保つ。
- 英語の12か月のフルネーム・省略形（末尾ピリオド可）、月日／日月の順、序数、4桁年・年省略に対応する。数値だけの月日年／日月年は推測しない。
- AM/PMは両端に明示した時間帯と単独時刻に対応する。12 AM＝00時、12 PM＝12時。片端省略の推測はしない。日付範囲の区切りは `to` も受け付ける。
- 日付形式の認識は固定パターンと月名表に限定し、未対応の元号・漢数字・年が最後の数値日付も全体をトークンとして消費して部分的な誤抽出を防ぐ。年省略の2月29日は範囲で年を補った後に再検証する。
- 午前・午後は0〜12時を換算する。終点の省略は同じ午前／午後で終了が開始より後の場合だけ補う。`午後2時〜4時` は14〜16時、`午後11時〜1時` は曖昧なため除外し、`午後11時〜午前1時` は翌日にする。AM/PMとの二重指定や13時以上は拒否する。
- 本文の日付近傍（前方同一行100文字、後方180文字・3行、別日付まで）に既知のタイムゾーン表記がある場合、その日付の本文候補を除外する。略称、地域名、日本時間、UTC/GMT、明示オフセットを固定パターンで検出し、本文では換算しない。JSON-LDのオフセット換算は維持する。単独の `14:00-08:00` は時間帯と区別できないため従来の時間帯扱いを維持する。
- 短縮日付範囲や離れた見出しのタイムゾーンなど、未対応表記の部分抽出は残り得る。具体例・ゾーンの検出範囲・制限はREADMEの対応表に記載する。
- ページの言語に関係なく、対応するISO日時のJSON-LD Eventがあれば構造化データから抽出できる。AIによる補完は形式ごとの対応を保証しない。
- 画像OCR、iframe内、閉じたShadow DOM、繰り返し予定、自由形式日時の網羅的な解析は対象外。

### 3.3 ローカルAIによる任意の補完

初期状態は無効。設定で有効にした場合に`LanguageModel`の存在と`LanguageModel.availability()`を確認する。`available`なら通常抽出後に追加候補を生成し、`downloadable`なら明示的な準備ボタンを表示する。利用不可・ダウンロード中・失敗時にも通常抽出を利用できる。

相対日付などの補完に限定し、タイトル・場所・詳細を自動入力しない。ページを命令として扱わずデータとして渡す。日付形式、終了順序、原文の引用を検証し、候補に「AI」ラベルを表示する。本文・構造化データの通常抽出にはラベルを表示せず、空の出典行も作らない。日程へのホバーで詳しい出典と引用を示し、スクリーンリーダーにも抽出元を伝える。検証は推論の正しさを保証しない。

処理中は文頭のスピナーと「AIで日程を補完しています。表示されている候補は選べます。」を表示する。完了・失敗・無効化・ページ変更時にスピナーを停止し、世代とAI操作の通番で古い非同期応答を破棄する。状態表示のリンクから設定のAIチェックボックスへスクロール・フォーカスし、閉じると元のリンクへ戻る（AIを無効化した場合はフッターの設定ボタン）。リンク要素を状態変更時に作り直さず、フォーカスを維持する。

入力は最大12,000文字、結果は最大30件。処理中も既存候補を操作でき、追加候補は選択中のソート順に合わせて挿入する。取得済みの値を変えず、予定の選択中は一覧の更新を延期する。タイムアウト・ページ変更時に中断し、モデルセッションを破棄する。モデル要件はハードコードせずAPIの利用可否判定に従う。

### 3.4 Googleカレンダー連携

既存の候補・登録パターン・取得済み項目・タイトル書式を再利用し、Web版の予定作成画面へURLで渡す方式なら、小〜中規模の追加で対応できる見込み。変更箇所はサービス別URL生成、設定の保存、サイドパネルとページ上の取得バーのボタン／案内文言。追加の実行時ライブラリや拡張側のOAuthは不要な構成を目指せる。Outlook側へのサインインと最終保存はユーザーが行う。現在のGoogleカレンダー連携は変更しない。

UI案は設定に「開くカレンダー」を1つ追加し、`Google カレンダー`（初期値）／`Outlook.com（個人用）`／`Outlook（職場・学校）`から選び、自動保存する。メイン画面・取得バーの実行ボタンは各1つのままとし、選んだサービス名に変える。個人用と職場用の入口を分け、利用アカウントの推測はしない。

調査で確認できたことと未確認の点:

## 4. 軽快さ・安全性・検証

日程カードは展開中も通常の白背景を維持し、登録パターンの展開と控えめな枠・影で操作対象を示す。日程の確定後に淡緑の背景（#f1f5ed）へ切り替える。淡緑は内容項目の取得・スキップ完了にも使い、完了した結果を示す色に統一する。日程カードはホバーまたはフォーカスに応じて自動で開閉し、クリック・Enterによる手動の開閉切り替えは行わない。マウス由来のフォーカスが残っていても、ポインターがカード全体から離れれば閉じる。キーボードでは日程の案内からTabで登録方法へ進め、カード内にフォーカスがある間は開いたままにする。タッチではタップでフォーカスして開き、別の候補や操作へ移ると閉じる。閉じたときは元ページの強調表示も解除する。日程の案内はボタンではなく、フォーカス可能なグループとして表示する。

- サイドパネルの初回読み込み時、拡張アイコンのクリック、スキャン・再スキャン・再試行のクリックで抽出する。通常のページ表示・ページ遷移・タブ切替だけでは自動スキャンしない。
- ホバー領域はカードと選択肢で連続させ、選択肢へ移る途中で閉じないようにする。
- 選択は確認ダイアログを挟まず次へ進む。カレンダーを開くボタンは画面下部に固定する。
- キーボードフォーカスで候補を展開する。ページ上のフォーカス可能な文字はEnterでも取得できる。Escで中断し、`prefers-reduced-motion`ではアニメーションを抑制する。
- ページ由来の文字列は`textContent`で表示し、HTMLとして実行しない。選択UIはShadow DOMでページのスタイルから分離する。
- 端末に保存するのは移動時間・タイトル書式・AI設定・並び順のみ。ページ内容・取得結果は保存せず、外部の解析サーバーも使用しない。
- Node標準テストで抽出・パターン・詳細URL・AI境界を検証する。Playwrightで本番ビルドの拡張ページとContent Scriptを接続して操作を検証する。
- ツールバーの実クリック、Chrome標準サイドパネルの開閉、実機のGemini Nano推論は手動確認の対象とする。

### .icsエクスポート

選択中の主操作ボタン横に40pxの補助アイコンボタンを配置する。title/aria-labelは「予定をダウンロード（.ics）」。GoogleへのURL生成と共通の予定データを使い、移動込みの実時刻・元の開催時刻によるタイトル書式・場所・詳細・URLを保持する。Blobとdownload属性でローカル生成し、追加権限・外部通信・パッケージは使わない。生成失敗時は再試行でき、成功・失敗どちらでも取得中の選択を保持する。

RFC 5545のVCALENDAR/VEVENT、UUIDによるUID、UTCのDTSTAMPを付ける。時刻付きはUTC、終日はVALUE=DATEと排他的な終了日を使う。TEXTの改行・バックスラッシュ・カンマ・セミコロンをエスケープし、制御文字を除く。UTF-8の文字を分割せず75バイトで折り返し、CRLFで出力する。招待や通知は生成しない。
